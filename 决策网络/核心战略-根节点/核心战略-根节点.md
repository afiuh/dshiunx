# 核心战略-根节点

**父级**：无

## 为什么要做

DSH 的理念对（一切皆插件，智能体本身也只是插件），但实现被产品稀释：

1. **产品包袱**：Web UI、账户、遥测、插件市场、多客户端适配
2. **为普适性做取舍**：框架里塞入了产品假设（默认界面、默认流程、平台集成）
3. **框架与产品耦合**：插件系统为产品功能服务，而不是为"创造"服务

## 要做什么

做一个与操作系统同构的 AI 程序：框架像 Arch 最初的模样一样简洁干净，其他一切都可以插件化，再加上自进化机制。

> 用户（2026-10-22，核心战略）：
> "dsh的理念很好，但是dsh本身太重了，而且为了产品的普适性，也在自己的理念上做了一些取舍，我们就是要更好地实现他这个理念，最初的框架应该就像 Arch Linux 系统最初的模样一样简洁干净，其他的一切都可以插件化，这种理念实行起来，其实就和Linux系统一切皆文件的理念是同构的，在这个框架上加的所有东西都能进行精确管理控制优化还能随意创造，再加上自进化机制，你想想，这样做出来的才是能更好地实现一切皆插件的本意吧"

**不是真的做一个操作系统**：dshiunx 本身仍是程序，与操作系统同构的是理念与架构（内核/进程/文件系统/窗口管理器/应用），不是实现一个 OS。

> 用户（2026-10-22，修正"同构"）：
> "澄清'同构'不是做 OS——dshiunx 本身仍是程序，与操作系统同构的是理念与架构。"

## 怎么做

### 三个层次

| 层次 | 目标 | 代码位置（已验证） |
|---|---|---|
| **内核** | 只保留不可插件化的机制：DI、生命周期、服务、事件、插件加载 | `packages/cordis/src/`（context/events/fiber/logger/reflect/registry/service/utils） |
| **插件** | 工具、界面、Agent 循环、记忆、装配——全部是插件 | `packages/dsh-*`（76 个） |
| **演化** | AI 是内核的一部分，能在运行时改造系统 | `dsh-agent-loop` + `dsh-tools` |

### 六条原则（从原话提炼）

**P1 最小内核**：框架像 Arch 最初的模样——简洁干净。

内核准入判据（必须全部满足）：
1. 所有插件都依赖它（不是某类插件）
2. 与具体能力无关（不知道"文件""工具""界面"是什么）
3. 足够稳定

内核职责清单（代码已验证）：
- 依赖注入（`ctx.inject` / `provide` / `get`，见 `registry.ts` / `reflect.ts`）
- 生命周期（`fiber.ts`，effect、dispose）
- 服务注册与查找（`service.ts`）
- 事件分发（`events.ts`：emit / waterfall / parallel / serial / bail，5 种）
- 插件加载（`cordis-plugin-loader`）

**明确不进内核**：TUI、Agent 循环、工具、模型适配器、会话存储、布局、角色、预设。

**P2 一切皆插件**：工具、界面、循环、记忆、装配、角色——全部是插件。不存在"系统固有功能"。

**P3 无限嵌套**：插件套插件，深度不设限；第 N 层子插件和顶层插件拥有同样的 ctx 能力。

代码已验证：`Context.extend()` / `isolate()` / `intercept()` 创建子上下文；`isolate` 让同名服务在不同 scope 有不同实现。

**P4 与操作系统同构**（设计语言，不是实现目标）：

| Linux | dshiunx | 代码位置 |
|---|---|---|
| 内核（调度/决策） | AI（agent-loop） | `dsh-agent-loop` |
| 进程 | session | `dsh-session` |
| 文件系统 | storage + entries.yml | `dsh-session-persistence-jsonl` + `bundle-arch/entries.yml` |
| 一切皆文件 | 一切皆插件/服务 | `packages/dsh-*` |
| 内核态 / 用户态 | 内核 / 插件 | `cordis` / `dsh-*` |
| 窗口管理器 | LayoutTree（平铺） | 未实现（TUI 封存） |
| 应用 | plugin | `dsh-*` |
| 包管理 | 插件加载器 | `cordis-plugin-loader` |

**P5 可管理、可控制、可优化、可创造**：精确管理、控制、优化、随意创造。

代码已验证：每个包有 `package.json`（manifest）、依赖、生命周期、配置 schema（schemastery）、隔离边界（isolate）。

**P6 自进化**：不是"AI 帮你写代码"，是 AI 作为内核的一部分，能在运行时改造系统。

当前状态：`dsh-agent-loop` 是插件，`dsh-tools` 是插件——AI 能改的正是这些。内核（cordis）是唯一不能自进化的部分。

## 如何验证自己做对了

- **welcome**：删掉所有可选插件，`dx` 仍能完成一次完整对话
- **anything**：任意插件可叠加/移除，不影响最小窗口
- **无产品假设**：默认界面里没有审批弹窗、市场入口、账户
- **可替换**：TUI、Agent 循环、模型适配器都能换成别的实现，内核不动
- **内核干净**：`grep -r "session\|tool\|llm\|ui" packages/cordis/src` 为空
- 人看：像不像 Arch——黑屏 + login，但登录后能用；不是桌面环境
