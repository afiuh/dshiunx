# dshiunx

> **与操作系统同构的 AI 程序**：最小内核 + 一切皆插件 + 自进化。
>
> 110 个包 / 10.9 万行 TypeScript / 38 个决策节点 —— **推进中，尚未达到"可体验"**。

---

## 这是什么

dshiunx 不是"又一个 AI 工具"，是一次**架构层面的实验**：把 AI 程序按操作系统的样子重新组织。

| Linux | dshiunx |
|---|---|
| 内核（调度/决策） | AI（agent-loop） |
| 进程 | session |
| 文件系统 | storage + 决策网络 |
| 一切皆文件 | 一切皆插件/服务 |
| 内核态 / 用户态 | 内核 / 插件 |
| 包管理 | 插件加载器 |

**不是真的做操作系统**——同构的是理念与架构，不是实现一个 OS。

## 与 DSH 的区别

DSH 的理念是对的：一切皆插件，智能体本身也只是插件。但它的实现被产品稀释了：

- **产品包袱**：Web UI、账户、遥测、插件市场、多客户端适配
- **为普适性取舍**：框架里塞入产品假设（默认界面、默认流程、平台集成）
- **"一切皆插件"只做了一半**：Agent 循环、预设、沙箱被做成**隐性内核**——它们是插件，但有专属注册路径、专属生命周期、专属 UI 位置，不能像普通插件一样热重载

dshiunx 要做的是**更激进地实现 DSH 没实现的事**：

| DSH | dshiunx |
|---|---|
| 插件分三六九等（基础/预设/业务） | **同质**：除内核外所有插件是同一性质的对象 |
| 插件部分显式（模型看不到 agent-loop、sandbox） | **显式**：每个插件对人和模型都可见 |
| 预设插件不能热启动 | **可热启动**：任何插件（含 Agent 循环）都能热重载 |
| 预设是"配置快照" | **热更新是默认**，冻结是显式选择 |

## 核心理念（六条原则）

1. **最小内核**：只保留不可插件化的机制——依赖注入、生命周期、服务注册、事件分发、插件加载
2. **一切皆插件**：工具、界面、Agent 循环、记忆、装配、角色——全部是插件，不存在"系统固有功能"
3. **无限嵌套**：插件套插件，深度不设限；第 N 层子插件和顶层插件拥有同样的 ctx 能力
4. **与操作系统同构**：设计语言，不是实现目标
5. **可管理、可控制、可优化、可创造**
6. **自进化**：AI 是内核的一部分，能在运行时改造系统

## 当前状态：推进中

**这是一个架构创新项目，不是"随便做几天就能用"的工具。**

我们前一段时间研究出了**决策网络驱动的动态多层智能体循环架构**，这导致项目规划发生了根本改变：

- **不会在这个项目里采用常规的智能体循环**（turn/step + 上下文累积）
- 要等决策网络驱动的动态多层循环实现后，再把它接入
- 在那之前，项目保持在"内核 + 插件体系"的推进阶段

**为什么值得等**：常规循环有三个天花板——

| 天花板 | 表现 |
|---|---|
| **上下文** | 跑几天上下文爆了，必须压缩、重启、丢记忆 |
| **理解** | 项目一大就"记不住"，多轮之后跑偏 |
| **协作** | 多 Agent 靠消息对齐，成本随数量平方增长 |

三个天花板的共同点不是"模型不够聪明"，是**结构缺失**：记忆没有外置、知识没有分层、接口没有统一。

决策网络就是补这个结构：把项目变成**可寻址的功能节点树**，AI 读节点边界而不是读全文；每层节点按同样的规则展开，深度不设限。

**这不是几周能做完的事**——它要求重写循环、重写上下文管理、重写工具调度。所以我们先做内核和插件体系，把地基打牢。

| 项 | 状态 |
|---|---|
| **内核** | `packages/cordis`（DI、生命周期、事件、插件加载），51 个内核包全部 ACTIVE |

## 架构

```
dshiunx/
├── packages/
│   ├── cordis/              # 内核：DI、生命周期、事件、插件加载
│   ├── cordis-plugin-*/     # 内核插件：loader、hmr、group、include、timer
│   └── dsh-*/               # 110 个功能插件
├── decisions/               # 决策网络（项目的结构化知识）
│   └── 核心战略.md
│       └── 核心战略-子节点/
│           ├── 内核模块.md
│           ├── 插件模块.md   ← 插件机制的指导理念
│           ├── 呈现.md       ← 思考的可见性
│           ├── 决策网络.md
│           └── 装配.md
├── bin/
│   ├── headless.ts          # headless 入口
│   └── dshiunx.ts           # 主入口
└── tests/                   # 6 个测试文件
```
