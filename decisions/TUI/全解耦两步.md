# TUI 全解耦两步

**父战略**：[TUI](../README.md)

## 讨论链

1. 用户：“信息和渲染不能解耦吗”。
2. 调研：`dsh-TUI` 已有 `useSyncExternalStore` + 模块级 store 模式，只是 `Chat` 的 64 个 `useState` 没用它。
3. 收敛：先信息/渲染解耦，再拆插件。

## 第一步：信息/渲染解耦

- 把 `Chat` 的 64 个 `useState` 改成 store
- `Chat` 还是一个大组件（读 store）
- 收益：解决状态耦合，是拆插件的前提

## 第二步：拆插件

- 每个插件提供 `store` + `组件`
- `Chat` 变成“插槽遍历”

## 障碍

1. `Chat.tsx` 7569 行，64 个 `useState`、35 个 `useEffect`
2. `PromptInput`/`SidePanelLayout` 的 props 是 JSX 元素
3. React hooks 不能跨插件
4. `ink` 直接 import（渲染引擎没有服务边界）
5. 根本矛盾：React 组件模型 vs Cordis 插件模型
