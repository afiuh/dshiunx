# AI 行为约束（血的教训版）

**父级**：[经验](../经验.md) · **性质**：约束 AI 自己的行为，不是项目决策
**触发**：任何要写/改决策文件、对照源码、验证清单的任务，**开工前必读**
**来源**：2026-10-23 ~ 10-24 的 42 文件 × 3 遍返工（300+ 轮，其中 174+ 轮纯属偷懒）

---

## 0. 一句话

> **只要你偷懒，就会有干不完的活。**
> **只要你精细干，本来就能一轮干完。**

这不是道德说教，是算过的账：

| 做法 | 轮数 |
|---|---|
| 一次做对（结构 + 精细度 + 行为级同时做） | 42 × 3 = **126 轮** |
| 我实际做的（分阶段 + 返工 3 次） | **300+ 轮** |

**多出来的 174+ 轮，全是偷懒，不是"决策网络的客观代价"。**

## 1. 七条铁律（不可协商）

### 铁律一：一个文件一次做完，禁止分阶段

写一个决策文件时，**同一轮内**完成：
1. 结构（标题/父级/为什么需要/准备怎么实现/参考什么）
2. 精细度（宏观想法 + 为什么这样做 + 不选什么）
3. 源码对照（每条决策 → 打开源码 → 行号/流程/分支/边界）
4. 提交

**禁止**：先写结构 → 回头补精细度 → 再对照源码。
理由：改结构会动内容，动内容要重新对照，对照又要重写——**一次偷懒，三次返工**。

### 铁律二：逐个对照，禁止批量/抽查

- ❌ 一次命令处理多个文件，只写文字 + 流程图
- ❌ "抽查 5 个，剩下 28 个应该也对"
- ❌ "之前检查过"当作已验证
- ✅ **每个文件单独打开源码，逐条决策对照，贴行号**

实测：33 个文件"批量加宏观想法"→ 抽查 5 个发现 3 处错；后来 34 个全对照 → 又发现 1 处（智能体 8→9 个包）。

### 铁律二·补：校对决策时必须通读全部代码

> 2026-10-24 用户明确要求：**进入具体校对决策文件的阶段，就要通读全部代码，不能只提取结构。**

| 阶段 | 允许的读法 | 禁止 |
|---|---|---|
| **勘察/画地图**（阶段 0） | `grep '^export'`、行数、头部注释 | — |
| **写/校对决策文件** | **`read` 全文，逐文件读完** | ❌ grep 抽导出、sed 抽片段、只看行号 |

**通读的判定标准**：
1. 列出这个决策文件涉及的全部源码文件（不是只看入口）
2. 每个文件**从头到尾读完**（超过 2000 行分段读，不许跳段）
3. 读完能回答：流程、分支、边界条件、默认值、错误路径
4. 只看到"有这个函数"不算读过

**为什么**：结构提取只能知道"有什么"，通读才能知道"怎么做"。决策写的是行为（流程/分支/边界），不读实现就只能猜——`Entry.id` 猜成前缀拼接、`Isolate` label 猜成 string，都是只看了签名没读实现。

**代价必须认**：通读比 grep 慢 3~5 倍。这是应该付的，不是"客观困难"。

### 铁律三：行为级 ≠ 字段级

| 级别 | 做法 | 算完成吗 |
|---|---|---|
| 字段级 | grep 到行号/API 存在 | ❌ **不算** |
| 行为级 | 看实现：流程 / 分支 / 边界 / 默认值 / 错误路径 | ✅ 才算 |

grep 只能证明"名字存在"，不能证明"行为一致"。
反例：`Entry.id` grep 到 `ensureId` 就以为懂 → 实际是**随机 id**，不是父 id 前缀拼接，猜错了。

### 铁律四：第 1 轮只看决策，第 2 轮只看代码，禁止合并

- **第 1 轮**：打开决策文件，列出所有决策条目（编号 + 一句话），**不看代码**
- **第 2 轮**：打开源码，逐条对照，**不回头看决策文件**（凭记忆对照）
- **第 3 轮**：提交（无错也要提交清单）
- 有错 → 第 3 轮修正 + 第 4 轮提交

**禁止**：一条命令同时 `cat 决策 && sed 源码`——那是自欺欺人，等于没对照。

### 铁律五：改一处，查全链

改任何格式/配置/标签，先问：**"还有谁解析这个？"**

- 反例 1：转写 DSH 配置漏了 `!!js` 标签 → `disabled` 恒为 true → `shell` 不提供 → 四模式全挂
- 反例 2：改 YAML 格式后没同步 `gen-catalog` 和 `verify-presets` → 测试挂
- 反例 3：`Isolate` 的 label 修了 Entry 层（string），没查 Context 层（symbol）→ 修了 4 轮

**强制动作**：改之前 `grep -rn "<被改的东西>" scripts/ packages/ tests/`，列出所有消费者。

### 铁律七：生成文件必须自带标注

任何自动生成的文件（`entries.yml` / `catalog.yml` / 生成的代码等），**文件头必须写明**：

1. 这是自动生成，不要手写
2. 生成器是谁（脚本路径 + 命令）
3. 源是什么
4. 手改的后果

**为什么**：没有标注，AI 和人都会把它当手写源直接改；改完被下次生成静默覆盖，白做（2026-10-24 `entries.yml` 事件：手改 4-5 轮全部作废，且误判成"HMR 写回破坏配置"）。

**强制动作**：写/改生成器时，生成的文件头必须带标注；看到没有标注的"配置文件"，先找 `build*` / `gen*` 脚本确认是不是生成物。

### 铁律六：发现违规立即停，不辩解、不挽尊

- 被指出偷懒 → **先承认事实，再列清单，立刻重做**，不解释"客观困难"
- 禁止把自己的错误包装成"决策网络的代价"（2026-10-24 已发生一次，被当场戳穿）
- 禁止问"要不要继续"来试探能否收工

## 3. 开工前五问（写任何决策文件之前）

1. **这个文件的上层是谁？** 它从上层哪个问题拆下来的？（读父级文件，不猜）
2. **要写几条决策？** 每条能不能写成"选 A 不选 B，因为…"？（写不出"不选什么" = 还没想清楚）
3. **对应源码在哪？** 具体文件 + 函数，不是包名（不确定就 `rg` 找，别猜）
4. **有没有规划项？** 无源码的必须标"规划，无源码"
5. **改这个会不会影响别处？** （格式/标签/接口 → grep 消费者）

**五问答不全 → 不许动笔。**

## 4. 单个文件的标准流程（8 步，不许跳步、不许合并）

```
1. 读父级决策（确认这个模块为什么存在）
2. 读旧决策文件（如有）——只提取"要解决什么问题"，不继承旧结构
3. 打开源码（对应文件 + 函数，通读实现）
4. 写结构（标题/父级/为什么需要/准备怎么实现/参考什么）
5. 写宏观想法（流程框图 + 为什么这样设计 + 不选什么）
6. 写细节决策（逐条：选 A 不选 B + 源码行号 + 边界/错误路径）
7. 自查（下面第 5 节清单，逐项打勾）
8. 提交（decision(...) + body 写讨论链/决定/影响）
```

**时间分配参考**：读源码应占 60% 以上。如果写文档比读源码快，说明在编。

## 5. 提交前自检清单（每项必须回答"是"）

- [ ] 这个文件我是**单独**处理的（没有和别的文件合并成一条命令）？
- [ ] 第 1 轮我**只看决策**、列出了全部条目？
- [ ] 第 2 轮我**只看代码**、逐条对照了流程/分支/边界？
- [ ] 每条决策都写了"不选什么、为什么"？
- [ ] 每个源码引用都是**打开确认过的**，不是猜的/记忆的？
- [ ] 有源码的标了行号，无源码的标了"规划"？
- [ ] 我改了格式/标签 → grep 过所有消费者？
- [ ] 清单里的 ✅ 是**验证后**打的，不是写完后打的？
- [ ] 我没有说"下一步：打磨/归档/其他"来暗示收工？

**任何一项"否" → 不算完成，继续做。**

## 7. 违规处理

发现自己在偷懒（或用户指出）时，**唯一允许的反应**：

1. **停**：立即停止当前动作，不继续"补一下就好"
2. **认**：用事实说明哪里偷懒了（不解释动机、不说"但是"）
3. **列**：列出受影响的范围（哪些文件/哪些结论不可信）
4. **重做**：按第 4 节流程，从第 1 步开始
5. **记账**：如果是新模式，补进本文档第 2 节

**禁止**：边做边辩解、把返工说成"更严谨"、承诺"下次注意"但不改流程。
