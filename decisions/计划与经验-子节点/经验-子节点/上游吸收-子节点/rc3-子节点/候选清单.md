**D1/D2/D5 不吸收的判断依据**（2026-10-24 追查）：

| 证据 | 说明 |
|---|---|
| 依赖 `dsh-app-boot` 的 `evaluatePluginCompatibility` | **版本检查，违反 P7** |
| 依赖 `dsh-client-connection` | 面向 Web 客户端的 Discover 页，产品功能 |
| 依赖 `dsh-plugin-market-index` + `semver` | 市场索引与版本排序，服务"发现/安装" |
| `bundle-detail` 是 `plugin-detail` 的消费方 | 三者是一套市场功能 |

**结论**：市场是产品功能（核心战略 §6 允许作为插件存在），但当前不实现——它带着版本检查和客户端依赖，与 P7 / 最小内核冲突。若将来要做，需先剥离版本判定、改成纯插件。

**B4/B5/E7-E9 不吸收的判断依据**（2026-10-24 追查）：

| 项 | 证据 | 结论 |
|---|---|---|
| B4 | 新增 `rpc.ts` = birpc over newline-JSON；其余是 host binding 编码、namespace 拒绝类 | 运行时内部实现，决策层已覆盖（PTC执行.md 的"运行时模式"） |
| B5 | 只改 `api-catalog.ts`（头部注明生成物） | 生成物自动跟随，无逻辑变更 |
| E7 | 稳定的时间拒绝诊断码 | 错误诊断细节，第 2 步顺手对齐即可 |
| E8 | Web 服务器（+197） | 产品服务，不进内核 |
| E9 | 未启用的包（-441） | 不需要 |

**待定的判断依据**：
- **B4**（PTC 运行时重构）：内部实现，与决策无直接对应，除非 PTC 执行器要落地
- **B5**（tool-cordis）：检视工具的 API 目录扩展，属于工具能力
- **D1/D2**（plugin-market / plugin-detail）：新功能；按 P1（市场不进内核）应作为插件
- **E1-E3**（web fetch/ready/动态出现）：网络节点的具体改进
- **E7-E10**（schedule / webserver / session-controller / core-session）：运行时或会话的细节
