# 依赖注入与生命周期

**父级**：[内核模块](../内核模块.md)

## 为什么需要

Context / Fiber / Effect / Service / Registry / Reflect：服务怎么注册、查找、随生命周期创建和销毁。

## 要做什么（问题）

| # | 问题 | 为什么重要 |
|---|---|---|
| 1 | 插件怎么拿到服务？ | `ctx.inject` / `ctx.get`（依赖注入） |
| 2 | 服务怎么注册？ | `ctx.provide` / `Service` 基类 |
| 3 | 生命周期怎么管？ | fiber / effect / dispose（清理） |
| 4 | 服务怎么隔离？ | isolate / scope（见嵌套与隔离） |
| 5 | 服务查找是全局还是链？ | 全局 store（按 isolate 标签） |

## 准备怎么实现（核心决策 + 为什么）

| 决策 | 选了什么 | 不选什么 | 为什么 |
|---|---|---|---|
| 依赖注入 | Proxy + inject 声明 | 手动传参 | 插件解耦 |
| 服务查找 | 全局 store（按 isolate 标签） | fiber 链 | 兄弟 entry 也能看到（D40 修正） |
| 生命周期 | fiber + effect | 手动 dispose | 自动清理（卸载时） |
| 服务注册 | `provide` / `Service` | 全局单例 | 可替换 |
| 隔离 | isolate map | 进程隔离 | 轻量（同进程） |
