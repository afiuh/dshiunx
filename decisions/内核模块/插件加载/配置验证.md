# 配置验证

**父级**：[插件加载](./插件加载.md)

## 为什么需要

配置错了要早报错——不然运行时 undefined，难排查。

## 要做什么

插件配置的 schema 验证 + 默认值补齐 + 报错。

## 参考什么

- 源码：`packages/cordis/src/fiber.ts:50`（`resolveConfig`，从 `@deepseek-ai/cordis` 导入）

## 宏观想法

插件导出 Config（Standard Schema），loader 在 apply 前验证 + 补默认值。

```
Config schema → resolveConfig → 失败抛 ValidationError
```

## 准备怎么实现

### 细节实现

1. **Config schema 验证**（`resolveConfig`，`cordis/src/fiber.ts:50-62`）：无 schema 直接返回；`runtime.Config['~standard'].validate(config)`；异步校验不支持（`TypeError`）；成功返回 `result.value`（默认值补齐）
2. 未提供字段用 schema 默认值补齐（`result.value`，Standard Schema 行为）
3. 失败抛 `ValidationError`（`result.issues`），fiber 进入 `FAILED`
4. **明确报错**：`ValidationError: invalid config: ...`；宿主启动器打印错误并以非零状态退出
