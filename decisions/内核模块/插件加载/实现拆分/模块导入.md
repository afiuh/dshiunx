# 模块导入

**父级**：[插件加载](../插件加载.md)

## 为什么需要

模块说明符 → ESM 模块，归一导出形状。

## 准备怎么实现

### 宏观想法

插件可能是 ESM / CJS / default 三种导出形状，loader 必须**归一成一种**才能 `apply`。动态 `import()` 又不在静态依赖图里，HMR 需要单独登记。

```
specifier → import() → unwrapExports（归一）→ plugin.apply
                    └→ importModule（登记 dynamicDeps）
```

**为什么这样**：不归一的话，`apply` 要处理三种形状；不登记动态 import 的话，HMR 改不到它。

### 细节实现

1. **`EntryTree.import(name)`**（`config/tree.ts:112`）：模块说明符 → ESM 模块；`cordis:` 前缀走 `builtins`（`name.slice(7)`，内建插件）
2. **`unwrapExports`**（`index.ts:230-241`）：归一 ESM/CJS/default——`exports.default ?? exports`，`__esModule` 时再取 `default`（esbuild interop）
3. **`ctx.loader.importModule(specifier)`**（`index.ts:204-228`）：动态 import 登记到 `dynamicDeps`（HMR 追踪）；URL 从 `internal.resolve`/`resolveSync` 拿，相对路径用 `new URL(specifier, baseUrl)`
