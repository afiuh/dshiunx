# 三集合

**父级**：[热更新](../热更新.md)

## 为什么需要

把变更文件分成“要重载 / 不重载 / 全量重启”三类。

## 准备怎么实现

### 宏观想法

变更文件要**分类**才能决定「重载谁、不重载谁、全量重启」——一个集合不够。

```
stashed（直接改的）→ accepted（要重载的）→ declined（不重载的）→ externals（全量重启）
```

**为什么三个集合**：直接改的、依赖它的、不相关的处理方式不同；混在一起会误重载或漏重载。

### 细节实现

| 集合 | 含义 |
|---|---|
| `stashed`（`hmr/src/index.ts:76`） | 变更文件 |
| `accepted`（`:67`） | 需要重载的模块（变更文件 + 依赖它的模块） |
| `declined`（`:73`） | 不重载（externals + 没有 accepted 依赖者的模块） |

1. **`stashed`**：`change` 时加入（`hmr/src/index.ts:76/145`）——直接变更的文件
2. **`accepted`**：初始 = `stashed`，然后沿依赖图向上找「依赖它的模块」（`analyzeChanges`，`:193-230`）
3. **`declined`**：初始 = `externals`，然后所有依赖者都 declined 的模块（`:196`）
4. **externals 变更** → `loader.exit()` 全量重启（`:136`）
5. **递归传播**：`analyzeChanges` 用 `pending` 队列迭代，直到没有新变化（`:209-230`）
