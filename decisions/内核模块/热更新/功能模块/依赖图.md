# 依赖图

**父级**：[热更新](./热更新.md)

## 要做什么

知道“改一个文件，哪些插件要重载”——需要模块依赖图。

## 准备怎么实现

- **ESM `ModuleJob.linked`**（不选静态分析/正则）：运行时准确，不需要解析 import
- **`dynamicDeps` 补充**（动态 import）：`ctx.loader.importModule()` 登记

## 参考什么

- 源码：`packages/cordis-plugin-hmr/src/index.ts` 的 `loadDependencies()`
- Node ESM：`ModuleJob.linked`（`--expose-internals`）
- 动态 import：`ctx.loader.importModule()`（已实现）

## 决策

1. 从 ESM `ModuleJob.linked` 递归收集依赖
2. 跳过 `node:` 和 `node_modules`
3. 动态 `import()` 的子模块不在静态 `linked` 图里 → `ctx.loader.importModule(specifier)` 把模块 URL 记入 `dynamicDeps`，HMR 的 `loadDependencies` 合并追踪
4. 原子重载单元是**插件入口**：深层依赖变更会回溯到入口（fiber 是插件级）

## 边界

| 能追踪 | 不能追踪 |
|---|---|
| 静态 import 的深层依赖 | CJS 依赖（`require.cache`，不在 `loadCache`） |
| 动态 import（登记后） | 未登记的动态 import |
