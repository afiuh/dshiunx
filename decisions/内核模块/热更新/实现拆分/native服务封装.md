# native 服务封装

**父级**：[热更新](../热更新.md)

## 为什么需要

让 native 插件（pty / koffi / sixel）也能热更，不重启进程。

## 准备怎么实现

### 宏观想法

`.node` 文件加载后不能卸载——所以 native 必须**隔离在服务里**，插件只依赖服务接口。

```
插件 JS（经常变）→ 服务接口（稳定）→ native 实现（极少变）
```

**为什么三层**：`.node` 不能卸载，只能隔离；插件 JS 热更，句柄传引用，`.node` 升级才重启。（**规划，无源码**：基于 native 模块的加载特性）

### 细节实现

1. **三层边界**：插件 JS / 服务接口 / native 实现（`.node`）
2. **热更方式**：插件 JS 热更；native 句柄用 `serialize/restore` 传引用；`.node` 升级才重启 worker
3. **插件约束**：不得直接 `import` native 模块，必须依赖服务接口
4. **服务隔离**：native 实现隔离在服务里，可独立升级/替换


## 架构

```
插件 JS（经常变）→ 服务接口（稳定）→ native 实现（极少变）
```

| 层 | 变更频率 | 热更方式 |
|---|---|---|
| 插件 JS 代码 | 高 | ✅ 热更 |
| native 句柄（pty/连接） | 不重启 | ✅ `serialize/restore` 引用传递 |
| `.node` 文件 | 极低 | ⚠️ 重启 worker（主进程/会话不断） |

## 参考什么

- DSH：native 插件（`node-pty` / `koffi` / `sixel`）的加载方式
- 内核：`cordis` 的 `ctx.effect`（清理）


## 结论

日常改代码不重启；只有升级 `.node` 文件才重启 worker——合理边界，不是妥协。
