# 依赖图

**父级**：[热更新](../热更新.md)

## 要做什么

知道“改一个文件，哪些插件要重载”——需要模块依赖图。

## 准备怎么实现

### 宏观想法

要知道「改一个文件，哪些插件要重载」，需要一张**模块依赖图**。用 ESM `ModuleJob.linked`（运行时已解析）而不是自己解析 import——**运行时准确**，不用写解析器。

```
变更文件 → 沿 import 关系向上找 → 找到插件入口 → 重载
```

**为什么不用静态分析**：正则/AST 解析 import 会漏动态 import、条件 import；`linked` 是运行时事实。

### 细节实现

1. **从 ESM `ModuleJob.linked` 拿依赖**（`getLinked`，`hmr/src/index.ts:182-187`）——运行时已解析好的依赖，不用自己解析 import 语句
2. **递归收集**（`loadDependencies`，`:30`）——从入口一路向下，收集整棵依赖树
3. **跳过 `node:` 和 `node_modules`**（`isExcluded`，`:196`）——标准库/第三方包不参与热更
4. **动态 import 登记**：`ctx.loader.importModule(specifier)`（`loader/src/index.ts:204`）把模块 URL 记入 `dynamicDeps`，HMR 的 `loadDependencies` 合并追踪
5. **原子重载单元 = 插件入口**：深层依赖变更会回溯到入口（fiber 是插件级，不能只重载一个文件）


## 参考什么

- 源码：`packages/cordis-plugin-hmr/src/index.ts` 的 `loadDependencies()`
- Node ESM：`ModuleJob.linked`（`--expose-internals`）
- 动态 import：`ctx.loader.importModule()`（已实现）

## 决策

1. 从 ESM `ModuleJob.linked` 递归收集依赖（`hmr/src/index.ts:30`）
2. 跳过 `node:` 和 `node_modules`
3. 动态 `import()` 的子模块不在静态 `linked` 图里 → `ctx.loader.importModule(specifier)`（`loader/src/index.ts:204`） 把模块 URL 记入 `dynamicDeps`，HMR 的 `loadDependencies` 合并追踪
4. 原子重载单元是**插件入口**：深层依赖变更会回溯到入口（fiber 是插件级）

## 边界

| 能追踪 | 不能追踪 |
|---|---|
| 静态 import 的深层依赖 | CJS 依赖（`require.cache`，不在 `loadCache`） |
| 动态 import（登记后） | 未登记的动态 import |
