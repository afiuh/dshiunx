# 监听与防抖

**父级**：[热更新](../热更新.md)

## 为什么需要

HMR 的第一环：**没有文件变更检测，就没有热更新**。

- 上层（[热更新](../热更新.md)）的实现拆分：改文件 → 依赖图 → 三集合 → 重载
- 本实现解决「怎么知道文件变了、什么时候触发重载」

## 准备怎么实现

### 宏观想法

HMR 的第一环是「知道文件变了」——但不能每次文件事件都立即重载（一次保存可能触发多个事件，编辑器可能先写临时文件再 rename）。所以整体是：

```
监听（chokidar）→ 事件过滤（change/ignored）→ 防抖（debounce）→ 触发 partialReload
```

### 细节实现

1. **监听根目录**：`chokidar.watch(root)`，`root` 默认 `['.']`（`config.root ?? ['.']`）——监听整个项目，不只 `packages/`
2. **忽略规则**：`ignored: path => match(path)`，`match` 用 picomatch 编译 `config.ignored`（默认 `[]`）——忽略 `node_modules`/`.git` 等
3. **启动不触发**：`ignoreInitial: true`——启动时已有文件不触发 change
4. **事件过滤**（`change` 事件，4 个分支）：
   - **externals**（框架入口依赖）→ `loader.exit()` 全量重启（`hmr/src/index.ts:136`）
   - **`loadCache` 里** → 加入 `stashed` + 防抖后 `partialReload`（`:144-146`）
   - **Include 配置文件**（`entry.subtree.filename`）→ `include.refresh()` 重新读配置（`:149-155`）
   - **其他** → `ctx.emit('hmr/change', url)` 通知监听者（`:157`）
5. **进入 stashed**：`change` 时检查 `loadCache.has(url)`——在 ESM 缓存里才加入 `stashed`
6. **防抖**：`ctx.debounce(() => this.partialReload(), this.config.debounce ?? 100)`——一次保存的多个事件合并成一次重载
7. **为什么用 timer 服务**：`setTimeout` 不随 fiber dispose 清理；`ctx.debounce` 绑定 effect，dispose 时自动取消（否则 HMR 插件卸载后定时器还在跑）
8. **配置默认值**：`root` 默认 `['.']`、`ignored` 默认 `[]`、`debounce` 默认 `100`——DSH 原版没默认值，启动时 undefined 会导致 chokidar 报错
9. **为什么不展开 `...this.config`**：`config` 里有 `root`/`ignored`/`base`/`debounce`，展开会覆盖 chokidar 的 options（`cwd` 等）——只显式传需要的字段
