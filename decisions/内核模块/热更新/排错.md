# 排错

**父级**：[热更新](../热更新.md)

## 为什么需要

HMR 不生效要能定位——缓存/模块格式是最容易踩的坑。

## 参考什么

- 排错记录：2026-10-22（`loadCache` vs `require.cache`）
- Node ESM：`package.json` 的 `type` 字段决定模块格式


## 准备怎么实现

### 宏观想法

“改了不生效”先确认文件在哪个缓存——ESM `loadCache` vs CJS `require.cache`。

```
change 触发？ → 在 loadCache？ → 在哪个缓存？ → 对比实验
```

### 细节实现


1. **change 是否触发**（加 `[hmr] change` 日志）
2. **在不在 `loadCache`**（加 `inCache` 日志；`hmr/src/index.ts:115`）
3. **在哪个缓存**（ESM `loadCache` vs CJS `require.cache`）
4. **对比实验**（临时目录加 `package.json`）

## 案例：改深层依赖，HMR 不重载（2026-10-22）

### 现象
改 `dep.ts`，`hmr/reload` 不触发，8 秒超时。

### 根因
测试临时目录（`mkdtempSync`）没有 `package.json` → tsx 按 CJS 处理 `.ts` 依赖（走 `require.cache`）→ HMR 只检查 ESM `loadCache` → 跳过。

### 修复
测试临时目录加 `package.json`（`{"type": "module"}`）。

### 教训
- “改了不生效”先确认文件在哪个缓存
- 模块格式由 `package.json` 的 `type` 决定，不是文件扩展名
- HMR 追踪只覆盖 ESM；CJS 依赖需要额外处理

## 已知限制

- 深层依赖的模块格式取决于 `package.json`（没有 `"type": "module"` 时走 CJS，HMR 追踪不到）
- 动态 `import()` 的子模块不在静态 `linked` 图里（需 `ctx.loader.importModule` 登记）
- Service 内部运行时状态（进行中的流等）在 reload 时丢失
