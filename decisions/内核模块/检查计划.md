# 内核模块检查计划

**父级**：[内核模块](./内核模块.md)

## 目的

对照代码精细检查每个决策文件：修正错误 + 补精细度 + 回顾代码。

**为什么**：决策是后续开发的前提；写错决策比写错代码更麻烦（会误导后续所有工作）。

## 检查方法

### 定位顺序（每个文件）

1. **先定位决策文件**：要核实的决策文件 + 涉及的决策条目
2. **再定位代码范围**：决策对应的源码文件/函数（决策里的"相关源码"）
3. **再判断是否需要 DSH 参考**：只有涉及"与 DSH 的差异"或"vendor 来源"时才查 DSH

### 检查步骤

1. **决策逐条对照源码**：方法/字段/默认值/行号是否准确
2. **行为描述对照**：流程/顺序/边界是否准确
3. **与 DSH 的差异**：`diff` 确认（有意修改 vs 无差异）
4. **补精细度**：补源码行号、配置项、边界条件、反例

**记录**：每发现一处错误 → 修 → 提交（commit message 写原因）。
