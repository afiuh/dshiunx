## 准备怎么实现

### 宏观想法

插件之间要通信，但场景不同——通知（不等）、并发（等全部）、串行（短路）、组合（前一个的返回值给下一个）。所以提供 **5 种分发模式**，按场景选。

```
emit（同步） / parallel（并发） / serial（串行） / bail（短路） / waterfall（组合）
```

### 细节实现

1. **5 种分发模式**（`events.ts:183/194/204/217/234`）：`emit` / `parallel` / `serial` / `bail` / `waterfall`。
2. **`emit`**（`events.ts:194`）：同步调用监听器，不 await；适合通知类事件。
3. **`parallel`**（`events.ts:183`）：await 所有监听器（并发）。
4. **`serial`**（`events.ts:204`）：按注册顺序 await，直到某个监听器返回 bail 值。
5. **`bail`**（`events.ts:217`）：同步调用，第一个非 null/false/undefined 的返回值停止。
6. **`waterfall`**（`events.ts:234`）：组合返回值——前一个监听器的返回值作为后一个的输入。
7. **`on` / `once`**：注册监听器，返回 disposer；随 owning fiber 自动注销。
8. **事件类型通过 `declare module` 扩展**：`interface Events { ... }`。
9. **监听器选项**：`global`（跨 scope）、`prepend`（插到最前）；`options` 也可以是 boolean（`prepend` 的简写）。
10. **`on` / `once` 的 disposer**：返回 `true` 表示调用时监听器仍注册。
11. **`parallel` 的错误聚合**：`Promise.allSettled` 收集所有结果，有 rejection 时抛 `AggregateError`。
12. **`waterfall` 的 `next` 机制**：最后一个参数是 `next`，监听器从外到内组合；不调用 `next()` 就 veto 后续链。
13. **`dispatch` 的 this / filter / 诊断**：第一个参数若是 object/function 则作为 `thisArg`；按 `Context.filter` 过滤监听器（`global` 跳过）；非 `internal/` 事件会 emit `internal/dispatch`（诊断）。
14. **`serial` / `bail` 的监听器返回值**：必须显式返回 `undefined` 才不中断；任何非 `null` / `false` / `undefined` 的值都会被当作 bail 值（`log.push()` 返回的数字也会 bail）。
15. **`waterfall` 的 `next` 是最后一个参数**：`waterfall(name, ...args, next)`；监听器签名 `(...args, next)`，不调用 `next()` 就 veto 后续链。

1. **`emit`**（`events.ts:194`）：同步调用监听器，不 await——通知类事件
2. **`parallel`**（`:183`）：`Promise.allSettled` 等全部，有 rejection 抛 `AggregateError`——并发
3. **`serial`**（`:204`）：按注册顺序 await，直到某个返回 bail 值——串行短路
4. **`bail`**（`:217`）：同步，第一个非 null/false/undefined 的返回值停止
5. **`waterfall`**（`:234`）：前一个监听器的返回值作为后一个的输入
6. **监听器清理**：`on`/`once` 返回 disposer，随 owning fiber 自动注销（`ctx.effect`）
7. **`dispatch` 过滤**：按 `Context.filter` 过滤监听器（`global` 跳过）；非 `internal/` 事件 emit `internal/dispatch`（诊断）
