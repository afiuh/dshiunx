# 去包管理器化：tsconfig paths

**父战略**：[包管理与依赖](../README.md)

## 讨论链

1. 起点：依赖链反复出问题（npm 旧版 0.0.1、peer 解析、workspace:*、dsh-compact 404）。
2. 根因：vendor 的 package.json 保留了 DSH 的发布元数据（version/dependencies/peer），这些是为 npm 发布设计的；包管理器按这些字段解析依赖，导致旧版 404。
3. 验证：tsx 的 `tsconfig paths` 支持静态和动态 import（loader 用）。
4. 收敛：采用方案 A——去包管理器化。

## 决定

- 每个包的 package.json 只保留 `name` + `private` + `type` + `main` + `exports`
- 删除 `version`、`dependencies`、`peerDependencies`、`devDependencies`、`files`
- 所有 `@deepseek-ai/*` 依赖走 tsconfig paths
- 根 package.json 只装外部依赖 + tsx/typescript
- 不使用 pnpm workspace / workspace:* / lock 文件
- 包管理器只负责装外部依赖

## 代价

- 外部依赖清单手动维护（`deps.mjs` 可扫描源码生成）
- 部署时预编译需解析 paths
- 第三方插件复制到 `plugins/`，加 paths 映射
