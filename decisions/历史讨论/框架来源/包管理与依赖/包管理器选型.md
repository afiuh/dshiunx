# 包管理器选型：当前用 npm

**父战略**：[包管理与依赖](../历史讨论.md)

## 讨论链

1. 起点：DSH 上游用 pnpm，用户问“npm 是必须的吗”。
2. 判断：特化版依赖会删减，当前 26 个包、5 个外部运行时依赖，幽灵依赖风险可忽略。
3. 收敛：用 npm，保留纪律（提交 `package-lock.json`、依赖显式声明）。
4. 未来：规模上来（几十个包、需要 workspace 链接）再迁移 pnpm，成本 = 删 `node_modules` 重装。

## 用户原话

> “那我看他们选这种包管理器，是为了处理依赖问题，还有工作区安全问题喽”
> “如果是这两种问题的话，因为我们做的是特化版，依赖会经过删减”

## 决定

- 当前规模用 npm；不排除未来迁移 pnpm
- 提交 `package-lock.json`；依赖按需显式声明（见「去包管理器化」的待决策）

## 后续变化

后来「去包管理器化」进一步：内部包不走 npm 解析，改用 tsconfig paths；外部依赖仍由 npm 安装。
当前核心包已显式声明 `dependencies`（版本 `*`），与「去包管理器化」的“删除 dependencies”存在冲突，**依赖声明策略待重新决策**。
