# 内核 + 插件宿主分层

**父战略**：[架构分层](../历史讨论.md)

## 讨论链

1. 用户问能不能换语言重写内核，同时保留插件生态。
2. 判断：内核（DI/生命周期/加载）与插件运行时（Node）可以分层。
3. 收敛：预留 `dshiunx-core`（第一版 Node）与“插件宿主接口”（未来可替换）。

## 决定

- 第一版只实现 Node 版
- 接口边界按两层设计

## 修正（2026-10-23）

- **`dshiunx-core` 已废弃**：已移到 `_attic/dshiunx-20261022/dshiunx-core`；HMR 改用 `cordis-plugin-hmr`
- 分层设计保留：内核（cordis）+ 插件宿主接口（未来可替换）
- 插件形态开放（in-process / worker / 子进程 / 远程），见 `插件模块/插件规范/README.md` 5.2
