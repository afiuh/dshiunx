# 使用体验战略：TUI 优先 + 呈现解耦

**父战略**：[TUI](../历史讨论.md)

## 讨论链

1. 功能都有了，接下来打磨使用体验。
2. 用户欣赏 DeepSeek 的数据/日志清晰记录呈现策略和网页呈现。
3. 判断：TUI 和 Web 不是两个产品，是**两个 renderer**；共享同一套数据层（session/event + projection + storage）。
4. 收敛：先 TUI（最小、ANSI、不引重框架），从真实需求提炼呈现协议；Web 后做。

## 用户原话要点

1. 先做最精简的 TUI 入口（像 pi 一样）
2. 后面把渲染类、呈现类全部解耦
3. 信息流体系参考 Linux：数据清晰放在文件里，和呈现渲染解耦
4. 大任务模块：TUI 和网页渲染结合

## 决定

- 先 TUI
- 中间加**呈现协议**：把事件规范成 renderer 可消费的 `ViewEvent`
- Web 后做，复用同一套流
