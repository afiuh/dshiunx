## 准备怎么实现

### 宏观想法

插件要输出日志，但输出方式要可替换（console/file/远程）。所以 **Logger 是 Service（结构化 Message），Exporter 是独立插件（决定输出）**。

```
ctx.logger.info(...) → Message（结构化）→ Exporter（过滤/格式化/输出）
```

### 细节实现

1. **4 个级别**（`logger.ts:13`）：`error` / `warn` / `info` / `debug`。
2. **结构化 Message**：level、name、参数、时间戳（`logger.ts`）。
3. **Exporter 接口**：`levels`（过滤）、`formatters`（格式化）、`export(message)`（输出）。
4. **占位符格式化**：`%C` 等，`Logger.format()` 内置。
5. **命名 logger**：`ctx.logger(name)` 返回带名字的 logger。
6. **logger 是 Service**：随 owning fiber 注销。
7. **不做版本检查**（P7）：logger 只按名字解析。
8. **级别过滤优先级**：`exporter.levels[name]` > `levels.default` > `logger.level` > `INFO`。
9. **占位符**：`%c` / `%C` 等是自定义 formatter；`%o` / `%O` 在 Node exporter 里用 `util.inspect`（深度 Infinity、单行）。
10. **两种调用形式**：`ctx.logger()` 返回命名 logger；`ctx.logger.info()` 直接用默认 logger。
11. **`logger-console` 是独立插件**（不在内核）：`ConsoleExporter` 负责输出，支持颜色（`supports-color`）。
12. **结构化优先**：`Message` 是结构化记录（level、name、args、timestamp），格式化由 exporter 决定。

1. **4 个级别**（`logger.ts:13`）：`error`/`warn`/`info`/`debug`
2. **结构化 Message**：level、name、args、timestamp——格式化由 Exporter 决定
3. **Exporter 接口**：`levels`（过滤）、`formatters`（格式化）、`export(message)`（输出）
4. **级别过滤优先级**：`exporter.levels[name]` > `levels.default` > `logger.level` > `INFO`（`:155`）
5. **命名 logger**：`ctx.logger(name)` 返回带名字的 logger；`ctx.logger.info()` 用默认
6. **`logger-console` 是独立插件**：`ConsoleExporter` 负责输出（颜色用 `supports-color`）
7. **随 fiber 注销**：logger 是 Service，fiber dispose 后失效


### 启动日志分级（2026-10-24）

**原则**：没有报错就没有输出（[核心战略 §2.0](../核心战略.md)）。

| 日志 | 级别 | 理由 |
|---|---|---|
| 启动失败 / 插件加载失败 / 配置错误 | `error` / `warn` | 用户需要知道 |
| `hmr watching ...`（正常启动） | `debug` | 正常状态，不是信息 |
| `dx: loaded N entries` | 仅 `DX_VERBOSE=1` | 调试信息，不是用户关心的 |

**判据**：默认启动只有主题句 + 提示符；任何"正常状态"的日志都不该出现在 info 级别。
