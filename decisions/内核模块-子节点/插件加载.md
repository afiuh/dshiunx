## 为什么需要

## 准备怎么实现（核心决策 + 为什么）

### 细节实现

1. **Loader 是 EntryTree 的子类**：拥有 entry 树 + 持久化钩子（`write()` 由子类实现）。
2. **`EntryTree.import(name)`**（`config/tree.ts:113`）：模块说明符 → ESM 模块；`cordis:` 前缀走 `builtins`（内建插件）。
3. **`unwrapExports`**：归一 ESM / CJS / default 导出形状。
4. **树操作**：`create` / `remove` / `update`，每次操作写回配置。
5. **`internal/config` 钩子**：对 entry 的 config 做 `!!js` 表达式插值（树载体 Group/Include 跳过）。
6. **`internal/update` 钩子**（`index.ts:118-121`）：配置变更时把 fiber 的 config 写回 `entry.options.config`（用 `Config.simplify` 反向序列化）。
7. **`internal/plugin` 钩子**：fiber 创建时绑定 entry；用户自 dispose 时把 entry 标记 `disabled` 并写回。只处理“用户自 dispose”这一种，其余 5 种情况跳过：
   - case 1：fiber 已创建（`uid` 非 0）
   - case 2：fiber 未被 loader 跟踪（无 `entry`）
   - case 3：fiber 是 entry 下的子插件（`parent.fiber.entry === fiber.entry`）
   - case 4：fiber 因插件删除而 dispose（HMR 的 `registry.delete`，runtime 已不在 registry）
   - case 5：entry 所属树正在卸载（tree owner 无 uid 或 UNLOADING）
   - case 6：entry 已被 loader 标记 disabled
8. **`Service.check`**：`await` 拦截——loader 条目未加载完时，依赖者保持 pending。
9. **`locate(fiber)`**（`index.ts:190`）：找 fiber 所属的 entry id。
10. **`exit()`**（`index.ts:200`）：宿主钩子，用于全量重启（HMR 的 external 变更）。

11. **Config schema 验证**：插件导出 `Config`（Standard Schema），loader 在 `apply` 前调用 `resolveConfig` 验证；未提供字段用 schema 默认值补齐；失败抛 `ValidationError`，fiber 进入 `FAILED`。
12. **Volatile 字段**：`.volatile()` 标记的字段，变化时更新稳定引用、**不重挂插件**；通过 `.get()` 读取；变化经 `loader/volatile-update` 事件通知（参数是变化路径）；loader 比较配置时忽略 volatile 字段。
13. **`!!js` 适用范围**：仅在 `config` 与 `disabled` 字段内有效；`disabled` 在每次挂载决策时基于 loader 上下文求值；其余元数据（`name`、`id`、`inject`）保持静态。
14. **明确报错**：配置无效时 `ValidationError: invalid config: ...`；fiber 进入 FAILED；宿主启动器打印错误并以非零状态退出。
15. **Include 是文件-backed EntryTree**：支持 YAML / JSON / JS；`path` 相对 `ctx.baseUrl` 解析。
16. **`!!js` 标签**：YAML schema 扩展（`tag:yaml.org,2002:js`），标量解析成 `{ __jsExpr }`，由 loader 在条目激活时求值。
17. **patch 语义**：`applyEntryPatches` 支持 `insert`（插到 group 或根）、按 id 覆盖字段、`name` 校验；未匹配的 patch 只 warn，不中断。
18. **initial 写入**：文件不存在（ENOENT）时写 `initial`；文件存在但解析失败必须报错，不能当成缺失。
19. **只读检测**：`access(W_OK)` 失败 → readonly；只读时不覆盖文件。
20. **refresh 容错**：重读文件，内容变化才 `root.update`；解析失败只 warn，保留旧树（热更新不能把进程搞挂）。
21. **原子写**：写临时文件 + `rename`；EACCES/EBUSY/EPERM 重试（10 次，递增延迟）；写操作串行化。
22. **`Entry.update` 路径**（`entry.ts:120`）：`create` 时整体替换 options，否则增量合并 + `sortKeys`（`entry.ts:37`）；`disabled` → dispose fiber；有 fiber 时计算 changes，volatile-only 走 `_commitVolatile`，否则 `loader/partial-dispose` + `_patchContext`；无 fiber → `init()`。
23. **`_commitVolatile` 细节**：用 `resolveConfig` 验证候选；普通值也变 → 返回 false 走普通更新；只 volatile 变 → `updateVolatile` + emit `loader/volatile-update`（带路径）；无效候选只 warn，运行中的引用不变；监听器异常只 warn，不影响更新。
24. **`init` 去重**：`_initTask`（`entry.ts:58/214`）保证并发 init 只跑一次；`_init` 失败只 `logger.error`，不创建 fiber。
25. **`EntryOptions` 的 string 索引签名**（`entry.ts:12`）：`[key: string]: any`，支持 patch 写入动态字段（`applyEntryPatches` 的 overrides）。

| 决策 | 选了什么 | 不选什么 | 为什么 |
|---|---|---|---|
| 树载体 | EntryTree 子类 | 独立数据结构 | 复用树操作（create/update/remove） |
| 模块导入 | ESM import + unwrapExports | require | 统一 ESM/CJS 导出形状 |
| 配置验证 | Standard Schema（`Config`） | 手写校验 | 插件自带 schema，loader 只调用 |
| 配置来源 | Include（文件-backed） | 硬编码 | 可热更（refresh） |
| 文件写入 | 原子写（temp + rename） | 直接写 | 防崩溃（写到一半断电） |
| 配置叠加 | patch（insert/覆盖） | 合并覆盖 | 多 bundle 组合（分层） |
| 版本检查 | 不做（P7） | semver | 结构契约（能跑就是能跑） |

## 与 Registry 的边界

| | Registry（依赖注入与生命周期） | Loader（本模块） |
|---|---|---|
| 管什么 | 内存中的插件注册表：`ctx.plugin()`、runtime、fiber 列表 | 从配置/文件到插件的路径：读 entries、import 模块、调 `ctx.plugin()` |
| 关键 API | `plugin()` / `inject()` / `delete()` / `values()` | `import()` / `create()` / `entries()` / `unwrapExports()` |
| 一句话 | “插件已经在内存里，我管它的实例” | “插件还在配置里，我把它变成实例” |

## 硬约束

- 加载不做版本验证（P7）
- 单个 entry 的失败被隔离，不阻塞其他条目
