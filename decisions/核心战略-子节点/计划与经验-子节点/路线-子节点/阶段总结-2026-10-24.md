## 2. 战略确认

### 2.1 主题（核心战略 §2.0）

> **welcome to dshiunx, you can do anything**

- **welcome**：默认有能用的起点（Arch 黑屏 + login）
- **you can do anything**：不预设用法，能力靠插件叠加（`pacman -S`）
- **dshiunx**：改造者不是复刻者

### 2.2 最小窗口的定义变了

| 之前 | 现在 |
|---|---|
| 最小窗口 = 轻量 TUI / REPL | **最小窗口 = Shell**（命令层） |
| TUI 是系统界面 | TUI 是**可选 renderer 插件** |
| 要不要做 TUI | 做，但它是"第一个应用"，不是"系统" |

### 2.3 架构形态

```
boot → shell → 一切
              ├─ 插件注册的命令（ls / cat / status / ...）
              ├─ 自启动的 renderer（default: tui / web）
              └─ 一次性任务（run / -p）
```

## 6. 下一步：加插件

Shell 已有命令注册表（`ctx.dxShell.register`），接下来按 Arch 命令集补齐：

| 命令 | 由谁注册 | 依赖 |
|---|---|---|
| `enable` / `disable` | plugin-manager | 改 profile patch |
| `install` / `remove` | plugin-manager | 安装流程 |
| `run "task"` | headless | 复用 `dsh-headless` |
| `tui` / `web` | renderer 插件 | 未来（TUI 已归档，可从零写轻量版） |

**原则**：加什么插件、加什么自启动，都从 shell 过一遍——入口不变。
