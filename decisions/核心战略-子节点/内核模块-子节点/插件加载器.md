# 插件加载器

**父级**：[内核模块](../内核模块.md)

## 要做什么

从 entries.yml 读条目，按 name 解析包、实例化、挂到 ctx，最后 `await` 所有插件就绪。

## 为什么要做

没有加载器，插件只能靠 import 硬编码；有了加载器，装配变成配置（YAML），换组合不改代码。

## 怎么做

### 代码事实（2026-11-07 验证）

- **是复刻**：`packages/cordis-plugin-loader/src/`（2026-11-07 曾被 checkout 误删，已从 feat/tui-reuse 恢复）
- 入口用法（`bin/headless.ts`）：

```ts
await ctx.plugin(Loader)
for (const entry of entries) {
  await ctx.loader.create({ id: entry.id, name: entry.name, config: entry.config })
}
await ctx.loader.await()
```

- `create`：解析包名 → import → 实例化 → 挂载
- `await`：等所有插件初始化完成（含异步）
- 失败：`EntryGroup.create` 没有 try/catch，`entry.update` 的错误会抛到调用方（`headless.ts` 的 for 循环会中断）——**不是"记录错误继续"**

### DSH 0.2.2 的变更（决策依据）

| 变更 | 决策含义 |
|---|---|
| `EntryTree.write()` **移除**，改 `commit(change: EntryChange)` | 子类实现 `commit`，同步接收 create/update/move/remove；内存树 no-op |
| Include 用 journal 持久化，`flush()` 等写盘 | 运行时改动**必须 flush** 才落盘；冲突时文件赢 |
| `perf(client-modules): index Loader entries once per flush` | 每次 flush 只重建一次索引——**dshiunx 包多（90 目录），这个收益大** |
| `fix(cordis): accept colon-containing entry ids` | 生成的 bundle id 带冒号——entries.yml 的 id 要允许冒号 |
| `fix(cordis): cross-tree group member transfer` | group 成员跨树移动不丢——无限嵌套直接依赖 |

**dshiunx 的决策**：
- `commit(change)`：**必须跟**（dshiunx 的 loader 继承 `EntryTree`，当前是旧版 `write()`）
- flush 索引：**建议跟**（性能）
- entry id 冒号：**必须跟**（entries.yml 可能生成带冒号的 id）
- 跨树移动：**必须跟**（无限嵌套是 P3）

## 边界

- 不检查版本兼容（npm 管）
- 不解析依赖图（YAML 顺序即顺序）
- 不热替换（HMR 是另一个插件）

## 如何验证自己做对了

- 改 entries.yml 加一条，重启生效，入口代码不动
- 删一条，能力消失，其余不受影响
- `ls packages/cordis-plugin-loader/src` 能看到源码
