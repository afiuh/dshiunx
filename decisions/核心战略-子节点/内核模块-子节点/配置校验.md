# 配置校验

**父级**：[内核模块](../内核模块.md)

## 要做什么

用 Schema 描述插件配置，启动时校验，配置错就明确报错。

## 为什么要做

YAML 写错（字段名、类型）在运行时才炸，很难定位。Schema 让错误在启动时暴露。

## 怎么做

### 代码事实（2026-11-07 验证）

- `packages/schemastery/src/index.ts`：Schema 类型系统
- 类型：`From<X>`、`TypeS<X>`、`TypeT<X>`、`Resolve`、`IntersectS`、`IntersectT`
- 用法（从 dsh-tools 等包看）：`import z from '@deepseek-ai/schemastery'`，插件声明 config schema
- 校验发生在 cordis 的插件注册时（`registry.ts` 的 `Config?: StandardSchemaV1`），不是 loader 的 create

## 边界

- 不做运行时重校验（改配置要重启）
- 不做默认值推断（显式写）

## 如何验证自己做对了

- 把 `timeoutMs` 写成字符串，启动报错并指出字段
- 配置正确时无警告
- `grep -n "export interface Static" packages/schemastery/src/index.ts` 能看到 Schema 工厂
