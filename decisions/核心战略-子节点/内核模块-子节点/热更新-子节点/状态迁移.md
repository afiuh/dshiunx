# 状态迁移

**父级**：[热更新](../热更新.md)

## 为什么需要

reload 后保留插件状态（会话/连接/计时器不丢）。

## 准备怎么实现

### 宏观想法

reload 会重建 fiber，**模块级变量会丢**——需要显式的 `serialize/restore` 把状态从旧 plugin 搬到新 plugin。

```
旧 plugin.serialize() → state → 新 plugin.restore(state)
```

**为什么不用模块级变量**：模块重载会重新执行模块代码，变量重置。

### 细节实现

1. **reload 时调用**：旧 plugin 的 `serialize()`（`hmr/src/index.ts:359-362`）→ 新 plugin 的 `restore(state)`（`:371`）
2. **失败只 warn**：`restore` 抛错只 `logger.warn`，不阻断重载（状态可丢，重载优先）
3. **状态外置**：需要跨 reload 保留的状态放 storage/session，不放模块级变量（插件规范第 4 条）
4. **为什么不用模块级变量**：模块重载会重新执行模块代码，变量重置
