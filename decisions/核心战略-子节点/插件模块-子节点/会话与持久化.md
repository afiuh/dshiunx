# 会话与持久化

**父级**：[插件模块](../插件模块.md)

## 要做什么

把会话做成事件溯源的存储：每个事件（消息、工具调用、结果）追加到日志，持久化为 JSONL，可投影、可检查点、可迁移格式。

## 为什么要做

会话是"进程"——它的状态必须可恢复、可审计、可迁移。如果会话只存在内存里，长任务一崩就全丢。

> 用户（2026-10-22，核心战略）：
> "和 Linux 系统一切皆文件的理念是同构的。"

### 持久化（代码验证）

- 存储：`.dshiunx/sessions`（JSONL，`compression: none` 当前配置）
- `lease.ts`：租约（防止两个进程同时写同一会话）
- `generation.ts`：会话代际
- `zstd.ts`：压缩（配置可开）
- `migration-verifier.ts`：迁移后校验
- `win32.ts`：Windows 路径处理

### 事件流

```
session/event（追加，带 seq）
  → projection（折叠）
  → checkpoint（持久化点）
  → 重启后恢复
```

### DSH 0.2.2 的变更（决策依据）

| 变更 | 决策含义 |
|---|---|
| `fix(session): migrate format v0 logs with subagent descriptor v1 and v2` | v0 会话里有 subagent descriptor v1/v2——**旧会话必须能读**，否则 fork/回放断 |
| `fix(session): require label in format v0 descriptor v1` | v0 descriptor 的 label 是必填——迁移器要补 |
| `perf(session): send one projection frame per committed event` | 投影从"多帧同 seq"变"一帧多 changes"——**长会话的帧数减半** |
| `projection-released-checkpoint`：`checkpoint(session)` 保留已释放单元最后一行 | 检查点不再省略最后一行——恢复时少一次重放 |
| `projection-snapshot-scope`：snapshot 只算返回的单元 | 大会话的 snapshot 读取变快 |

**dshiunx 的决策**：v0 迁移是**必须跟**（旧会话是资产）；投影一帧是**建议跟**（headless 直连，收益在长会话）。

## 边界

- **会话不存 UI 状态**：展开/折叠/滚动位置是前端的事
- **会话不做压缩**：压缩是 `compaction-*` 的事
- **会话不保证实时**：持久化是异步的，崩溃可能丢最后几条

## 如何验证自己做对了

- 跑一个任务，杀掉进程，重启后能从 JSONL 恢复
- 旧格式会话能被迁移器读出来（v0→v4）
- 检查点之后的事件不会重复执行
- fork 一个会话，子会话继承前缀、父会话不受影响
- 人看：`session.v4.jsonl` 是否一条事件一行、可读
