# 待办工具

**父级**：[工具](../工具.md)

## 要做什么

给模型 `todo_write`，把任务清单写进事件溯源的会话日志——整表替换，last-write-wins。

## 为什么要做

待办是长任务的锚点：模型能写、能读、能勾掉，人也能看到进度。存进会话日志（而不是内存），重启后还在。

## 怎么做

### 代码事实（2026-11-07 验证）

`packages/dsh-tool-todo/`（3 个源文件，269 行）：

| 文件 | 职责 |
|---|---|
| `index.ts` | `todo_write` 工具 + 投影注册 |
| `types.ts` | `TodoItem`、`todo/write` 事件、`todos` 投影 |
| `client.ts` | 浏览器半入口（客户端聚合用） |

### 工具定义（代码验证）

```ts
name: 'todo_write'
parameters: {
  todos: [{ content: string, status: 'pending' | 'in_progress' | 'completed' }]
}
output: { todos: TodoItem[], counts: ... }
```

- **整表替换**：每次写入是完整列表，不是增量
- **无 id / 优先级 / activeForm**：条目不需要稳定身份（last-write-wins）
- 三种状态：`pending`（未开始）/ `in_progress`（进行中）/ `completed`（完成）
- 配置 `allowParallelInProgress: true`：允许多个 `in_progress`

### 事件与投影（代码验证）

`types.ts` 声明：

```ts
declare module '@deepseek-ai/dsh-session/types' {
  interface SessionEventMap {
    'todo/write': { todos: TodoItem[] }   // 整表快照；回放时 last-wins
  }
}
declare module '@deepseek-ai/dsh-session-projection/types' {
  interface SessionProjectionStateMap { todos: TodoItem[] | null }
}
```

- 事件：`todo/write`（log-only UI state，不进入派生历史）
- 投影：`todos`（第一次写入前为 `null`）
- `stateVersion: 2`

### 与 DSH 的差异（代码验证）

DSH 的包在 `packages/todo/tool-todo/src/`：`client.ts` 两边相同；`index.ts`、`types.ts` 有差异（dshiunx 0.2.1-rc.2 vs DSH 0.2.2-rc.1）。

### 装配（entries.yml）

```yaml
- id: tool-todo
  name: '@deepseek-ai/dsh-tool-todo'
  config:
    allowParallelInProgress: true
```

## 边界

- **不做优先级排序**（模型自己决定）
- **不做提醒**（那是 repeat-tool-reminder）
- **不进派生历史**（log-only，不影响模型上下文）

## 如何验证自己做对了

- 写待办后重启，待办还在（投影从事件重建）
- 勾掉后状态更新，`counts` 正确
- 并发写多次，最后一次生效（last-wins）
- `grep -n "todo/write\|todos" packages/dsh-tool-todo/src/types.ts` 能看到事件与投影声明
- 人看：`TodoItem` 是否只有 `content` + `status` 两个字段
