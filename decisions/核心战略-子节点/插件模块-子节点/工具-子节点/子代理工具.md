# 子代理工具

**父级**：[工具](../工具.md)

## 要做什么

让模型把任务委派给子代理（两种模式：继承对话 / 自包含），并能 `send_message`、`interrupt_agent`、`list_agents`。

## 为什么要做

复杂任务需要拆给子代理；子代理的上下文隔离，主代理只拿结果，不消耗自己的上下文。

## 怎么做

### 代码事实（2026-11-07 验证）

| 包 | 工具 | 源码 |
|---|---|---|
| `dsh-tool-subagent` | 委派（两种模式） | `src/index.ts`、`list-models.ts`、`model-selection*.ts`、`preset-selection.ts` |
| `dsh-tool-subagent-control` | `send_message`、`interrupt_agent`、`list_agents` | `src/index.ts`、`list-agents.ts` |
| （无独立包） | `list_agents` | entries 里是 `@deepseek-ai/dsh-tool-subagent-control/list-agents`（control 包的子路径导出） |

### 两种委派模式（代码验证）

`providerWording(inheritsConversation)`：

**继承对话**（`inheritsConversation: true`）：
> "Delegate a task to a subagent that inherits this conversation: a child agent seeded with all completed turns so far (it does not see the current in-flight turn)..."

- 子代理看到已完成的所有 turn
- 适合：后续分析、评审、延续
- 不消耗主会话上下文

**自包含**（`false`）：
> "Delegate a self-contained task to a subagent (a separate agent that works in its own context)..."

- 子代理不共享主会话上下文
- 适合：独立研究、范围明确的实现、分析
- prompt 必须包含所有需要的信息

### 控制工具（代码验证）

| 工具 | 作用 |
|---|---|
| `send_message` | 给子代理发消息 |
| `interrupt_agent` | 中断子代理 |
| `list_agents` | 列出子代理 |

### 与 DSH 的差异（代码验证）

`diff`：**两个包的源文件完全一致**（DSH `packages/subagent/tool-subagent*` vs dshiunx）。

DSH 还有 `packages/experimental/tool-subagent-oar`（实验性），dshiunx 未装配。

### 装配（entries.yml）

```yaml
- id: tool-subagent-control
  name: '@deepseek-ai/dsh-tool-subagent-control'
- id: tool-subagent-list
  name: '@deepseek-ai/dsh-tool-subagent-control/list-agents'
- id: tool-subagent
  name: '@deepseek-ai/dsh-tool-subagent'
  config: ...
```

## 边界

- 子代理不直接和用户交互
- 不做无限嵌套（由配置控制）
- 子代理的中间步骤不返回（只返回结果）

## 如何验证自己做对了

- 委派一个继承对话的任务，子代理能看到之前的 turn
- 委派一个自包含任务，子代理看不到主会话
- `send_message` 能追加指令，`interrupt_agent` 能中断
- `diff` DSH 与 dshiunx 的 `src` = 一致
- 人看：两种模式的描述是否清楚区分"继承/不继承上下文"
