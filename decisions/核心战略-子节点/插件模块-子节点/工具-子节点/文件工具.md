# 文件工具

**父级**：[工具](../工具.md)

## 要做什么

给模型 `read`、`write`、`edit` 三个文件操作（`read_image` 可选），全部走 `ctx.fs` 服务。

## 为什么要做

读写文件是 coding agent 的基本能力；但它必须走 `ctx.fs` 服务，不能直接碰磁盘——沙箱、观察策略、工作目录都在服务层。

## 怎么做

### 代码事实（2026-11-07 验证）

`packages/dsh-tool-fs/`（12 个源文件，1561 行）：

| 文件 | 职责 |
|---|---|
| `read.ts` | `read` 工具（file_path / offset / limit） |
| `write.ts` | `write` 工具 |
| `edit.ts` | `edit` 工具 |
| `read-image.ts` | `read_image` 工具（配置 `readImage: false` 当前关闭） |

| `session-cwd.ts` | 会话工作目录 |
| `error.ts` / `index.ts` | 错误与注册 |

### 工具定义（代码验证）

`read`：

```ts
name: 'read'
description: 'Read a UTF-8 text file and return line-numbered content.'
parameters: {
  file_path: { type: 'string', required: true },
  offset: { type: 'number' },   // 1-based
  limit: { type: 'number' },
}
output: { path, offset, lines: [{ number, text }] }
```

`write` / `edit` 各有 `tool:xxx`（内部名）和 `xxx`（模型可见名）。

### 提示词注入（代码验证）

`read.ts` 在注册时调用 `ctx.systemPrompt.section({ name: 'tool:read', ... })`，注入：

> "Use the read tool — not shell commands like cat — to inspect text files. Use offset and limit to continue reading large files."

### 与 DSH 的差异（代码验证）

| DSH 0.2.2-rc.1（`packages/fs/tool-fs/src/`） | dshiunx 0.2.1-rc.2 |
|---|---|
| 有 `apply-patch.ts`、`apply-patch-output.ts`、`apply-patch-presentation.ts`、`patch/`（4 个文件，768 行） | **没有**（未跟进 0.2.2） |
| 其余文件 | 一致 |

**结论**：dshiunx 的文件工具落后一个版本——`apply_patch` 还没跟进。

### DSH 0.2.2 的变更（决策依据）

| 变更 | 决策含义 |
|---|---|
| `tool-fs` 新增 `applyPatchGuard` | `apply_patch` 可以**绕过 observation guards** 应用 hunk——这是"读后写"策略的逃生口 |
| `fs` 默认开 `apply_patch`，observation policy 改为可选 | 上游的判断是：**强制先读**在多数场景是摩擦，不是保护 |
| `write`/`edit` 的提示语仍要求先读，但不再引用策略 | 提示语保留，策略可关 |

**dshiunx 的决策（2026-11-07 已落地）**：

- **保留 `fs-observation-policy`**（读后写是唯一行为约束，沙箱是 `danger-full-access`）
- **`tool-fs` 加 `applyPatch: true`**（entries.yml 已配置）

验证：51/51 ACTIVE；headless 跑通。

### 装配（entries.yml）

```yaml
- id: tool-fs
  name: '@deepseek-ai/dsh-tool-fs'
  config:
    read: true
    readImage: false
    write: true
    edit: true
```

## 边界

- **不绕过 fs 服务**：沙箱/观察策略在服务层
- **不做批量操作**：逐个调用
- **不做 apply_patch**（当前）：DSH 0.2.2 有，dshiunx 未跟进

## 如何验证自己做对了

- 读一个文件，内容带行号
- 写一个文件，落盘
- edit 只改指定片段，`diff.ts` 能出差异
- `ls packages/dsh-tool-fs/src` = 12 个文件（DSH 是 16 个，差 apply-patch 的 4 个）
- 人看：三个工具是否都走 `ctx.fs`，没有直接 `fs.readFile`
