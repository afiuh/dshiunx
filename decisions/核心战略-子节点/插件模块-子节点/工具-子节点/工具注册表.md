# 工具注册表

**父级**：[工具](../工具.md)

## 要做什么

注册工具、生成给模型的 schema、执行工具调用，并在执行前后提供两个 waterfall（`tools/pre-execute`、`tools/execute`）；另外支持 PTC（把工具 schema 渲染成 Python/TypeScript 代码，让模型写程序调用）。

## 为什么要做

工具是智能体的能力边界。注册表让"加一个工具"= 加一个插件，不改循环。

> 用户（2026-10-22，核心战略）：
> "其他的一切都可以插件化……加的所有东西都能进行精确管理控制优化还能随意创造。"

## 怎么做

### 代码事实（2026-11-07 验证）

`packages/dsh-tools/`（10 个源文件，5782 行）：

| 文件 | 职责 |
|---|---|
| `index.ts` | 注册表、执行管线、事件定义 |
| `schema.ts` | 工具 schema（schemastery） |
| `json-schema.ts` | JSON Schema 校验（`assertSupportedJsonSchema`、`validateJsonSchemaValue`） |
| `presentation.ts` | 工具展示 |
| `ptc.ts` | PTC 运行时（`RUN_CODE_NAME`、`CodeRunFailedError`） |
| `ptc-calls.ts` | PTC 调用 |
| `py-types.ts` | 工具 schema → Python 代码（`jsonSchemaToPy`、`renderToolsSdkPy`） |
| `ts-types.ts` | 工具 schema → TypeScript 代码（`jsonSchemaToTs`、`renderToolsSdk`） |
| `types.ts` | 类型定义 |
| `testing.ts` | 测试夹具（`defineContentToolFixture`） |

### 事件（代码验证）

`index.ts` 的 `Events` 接口，共 6 个：

| 事件 | 作用 |
|---|---|
| `tools/pre-execute` | 执行前决策（`PreToolDecision`） |
| `tools/execute` | 执行（可改写参数/结果）；`dsh-tool-call-timeout-policy` 是它的 wrapper |
| `tools/post-execute` | 执行后 |
| `tools/result` | 结果发布 |
| `tools/change` | 工具注册表变更 |
| `tools/ptc-dispatch-log` | PTC 调度日志 |

### 与 DSH 的差异（代码验证）

| DSH（`packages/core/tools/src/`） | dshiunx（`packages/dsh-tools/src/`） |
|---|---|
| batch.ts、contracts.ts、events.ts、executor.ts、pipeline.ts | 合并进 `index.ts` |
| — | 新增 `ptc.ts`、`ptc-calls.ts`、`py-types.ts`、`ts-types.ts`、`testing.ts` |
| 共同 | index、json-schema、presentation、schema |

**结论**：dshiunx 复刻时做了两件事——把 DSH 的 5 个文件合并进 index.ts，加了 PTC 支持。

### 装配（entries.yml）

```yaml
- id: tools
  name: '@deepseek-ai/dsh-tools'
```

无配置。

## 边界

- **不做审批**：dshiunx 无审批
- **不做重试**：工具自己处理
- **PTC 不替代逐个调用**：两种模式并存

## 如何验证自己做对了

- 加一个工具包，entries.yml 加一行，模型能看到并调用
- 监听 `tools/execute` 能改写参数
- `grep -n "tools/pre-execute\|tools/execute" packages/dsh-tools/src/index.ts` 能看到两个事件
- `ls packages/dsh-tools/src` = 10 个文件（与 DSH 的 9 个不同）
- 人看：`index.ts` 是否只有"注册 → 校验 → 执行"三步
