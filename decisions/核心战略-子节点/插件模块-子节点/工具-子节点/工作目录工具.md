# 工作目录工具

**父级**：[工具](../工具.md)

## 要做什么

给模型 `working_directory` 工具：读当前会话的工作目录，或用 `cd` 改它。

## 为什么要做

多项目场景下，模型需要知道"现在在哪个目录"，并能切换；工作目录要持久化到会话，重启后保留。

## 怎么做

### 代码事实（2026-11-07 验证）

`packages/dsh-tool-working-directory/`（1 个源文件，42 行）：

```ts
name: 'working_directory'
description: 'Read the current working directory, or change it with cd. Relative paths use the current directory. Existing shells and running processes keep their own directories.'
parameters: {
  cd: string   // 省略 = 读取
}
output: { cwd: string }   // 绝对路径
```

执行：
```ts
const cwd = args.cd === undefined
  ? await ctx.workingDirectory.ensure(exec.agent, exec.signal)
  : await ctx.workingDirectory.set(exec.agent, args.cd, exec.signal)
return { cwd }
```

- 注入：`tools`、`workingDirectory`
- 需要 agent session（`exec.agent === undefined` 时抛错）
- **已有 shell 和运行中的进程保持自己的目录**（不追溯）

### 底层（代码验证）

`packages/dsh-working-directory/src/index.ts`：会话工作目录服务（`ensure` / `set`）。

### 与 DSH 的差异（代码验证）

`diff`：**源文件一致**（DSH `packages/session/tool-working-directory/src`）。

## 边界

- **不做目录浏览**（那是 glob/fs 工具）
- **不做权限检查**（沙箱管）
- **不追溯已启动的进程**（只影响后续调用）

## 如何验证自己做对了

- 改 cwd 后，后续工具在新区执行
- 重启后 cwd 保留
- 已有 shell 的目录不变（文档写明）
- `diff` DSH 与 dshiunx 的 `src` = 一致
- 人看：工具是否只有"读或设 → 返回绝对路径"
