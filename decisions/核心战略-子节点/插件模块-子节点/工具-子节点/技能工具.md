# 技能工具

**父级**：[工具](../工具.md)

## 要做什么

给模型 `skill` 工具：按名字加载一个技能的完整说明（SKILL.md），在动手前拿到领域知识。

## 为什么要做

技能是"预置的领域知识"，不该全塞进系统提示词；按需加载省上下文。

## 怎么做

### 代码事实（2026-11-07 验证）

`packages/dsh-tool-skill/`（1 个源文件，433 行）：

```ts
name: 'skill'
description: 'Load the full instructions for a skill. Call it before acting on a task that names or clearly matches a skill in the session skill catalog.'
parameters: { name: string }   // 技能目录里的精确名字
output: { name, provider, resourceBase, ... }
```

`resourceBase` 三种形态：
- `{ kind: 'directory', path }`
- `{ kind: 'url', url }`
- `{ kind: 'opaque', description }`

### 相关包（代码验证）

| 包 | 职责 | 源码 |
|---|---|---|
| `dsh-skill` | 技能注册表（provider 注册） | `src/index.ts` |
| `dsh-skill-filesystem` | 文件系统技能提供者（本地 SKILL.md） | `src/index.ts` |
| `dsh-tool-skill` | 模型可见的 `skill` 工具 | `src/index.ts` |

### 与 DSH 的差异（代码验证）

DSH 的包在 `packages/skill/tool-skill/src/`：同样是单文件 `index.ts`（451 行）；dshiunx 是 433 行（版本 0.2.1-rc.2 vs 0.2.2-rc.1 的差异）。

### 装配（entries.yml）

```yaml
- id: skill
  name: '@deepseek-ai/dsh-skill'
- id: skill-filesystem
  name: '@deepseek-ai/dsh-skill-filesystem'
- id: tool-skill
  name: '@deepseek-ai/dsh-tool-skill'
```

## 边界

- 技能是只读的
- 不做技能市场（那是产品功能）
- 不加载时，技能内容不在上下文里

## 如何验证自己做对了

- 加载一个技能，模型拿到完整说明
- 不加载时，技能内容不在上下文
- 技能名不存在时报错清楚
- `grep -n "name: 'skill'" packages/dsh-tool-skill/src/index.ts` 能看到定义
- 人看：工具是否只做"按名字取内容"，不解析技能语义
