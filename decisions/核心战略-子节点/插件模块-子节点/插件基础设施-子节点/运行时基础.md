# 运行时基础

**父级**：[插件基础设施](../插件基础设施.md)

## 为什么需要

插件不是悬空的：智能体要读会话、调模型；工具要起子进程、联网；界面要读投影。

这些服务**被多数插件依赖**，但它们本身不提供"能力"——不暴露给模型、不决定做什么。它们属于基础设施，不属于具体插件。

## 准备怎么实现

### 宏观想法

```
运行时基础（被用）
├── 会话/        记忆的载体：session / projection / persistence / storage
├── 模型/        说话的通道：llm / adapter / token-meter / retry
├── 网络/        联网能力：web / fetch / search provider
└── 运行时支撑/  执行的底座：subprocess / sandbox / attachment / jobs / compaction
```

**为什么归基础设施而不是具体插件**：判断标准是"被用还是再用"。
- 会话/模型/网络/运行时支撑 → **被**智能体、工具、界面使用
- 智能体/工具/界面 → **在**使用这些服务，提供具体能力

### 边界

| 属于运行时基础 | 不属于 |
|---|---|
| 通用服务的**契约与实现** | 把服务包装成模型可调用的工具（那是工具插件） |
| 资源生命周期（连接、进程、文件句柄） | 业务策略（如"什么时候该压缩"属于会话使用方） |
| 能力探测（可用/不可用） | 权限决策（审批在工具执行链上） |

**与内核的边界**：内核不知道"会话""模型"是什么；运行时基础知道，但不提供具体能力。

### 子节点

| 子节点 | 负责什么 | 主要包 |
|---|---|---|
| [会话](./运行时基础-子节点/会话.md) | 记忆的载体：事件流、投影、持久化、存储 | `session` / `session-projection` / `session-persistence-jsonl` / `storage*` |
| [模型](./运行时基础-子节点/模型.md) | 模型接入：适配器、路由、计量、重试 | `llm` / `llm-deepseek` / `token-meter` / `llm-retry` |
| [网络](./运行时基础-子节点/网络.md) | 联网能力：搜索与抓取的 provider | `web` / `web-fetch-http` / `web-search-deepseek` / `web-deepseek-api` |
| [运行时支撑](./运行时基础-子节点/运行时支撑.md) | 执行的底座：子进程、沙箱、附件、后台任务、压缩 | `subprocess*` / `sandbox*` / `attachment*` / `jobs*` / `compaction*` |

### 验证

- 删掉任一运行时基础服务，依赖它的插件明确失败（不静默降级）
- 运行时基础不 import 任何具体插件
- 换实现（如换 LLM 适配器）不改调用方代码
