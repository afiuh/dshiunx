# 模型层

**父级**：[插件模块](../插件模块.md)

## 要做什么

提供 provider 中立的 LLM 接口、DeepSeek 适配器、API Key 认证、请求重试——让模型成为可替换的插件。

## 为什么要做

模型是变化最快的一层：换 provider、换模型、换认证方式，都不该动 Agent 循环。

> 用户（2026-10-22）：
> "模型适配器——全部是插件。"

## 怎么做

### 代码事实（2026-11-07 验证）

| 包 | 职责 | 源码 |
|---|---|---|
| `dsh-llm` | provider 中立接口 | `src/`（13 个文件：message、content、assistant-stream、assembler、call-config、adapter-failure、retry-policy、api-key、attribution、brand、error、types、index） |
| `dsh-llm-deepseek` | DeepSeek Messages 适配 | `src/`（24 个文件：adapter、config、defaults、host、files-api、file-store、file-id、images、image-tokens、messages-api、model-info、models、replay、request-extensions、request-files、request-pricing、serialize、sse、translate、transport、upload-index、wire-types、types、index） |
| `dsh-llm-deepseek-api-key` | API Key 认证 + 模型发现 | — |
| `dsh-llm-retry` | provider 路由的重试 | — |

### 接口分层（代码验证）

```
dsh-llm（中立）
  ├── message.ts        消息类型
  ├── content.ts        内容块（text / image / tool-call）
  ├── assistant-stream.ts 流式块
  ├── assembler.ts      请求组装
  ├── call-config.ts    调用配置（provider/model/参数）
  ├── retry-policy.ts   重试策略（中立）
  ├── api-key.ts        API Key 格式校验（transport invariant）
  └── adapter-failure.ts 把 provider 异常转成中立事实
```

### DeepSeek 适配（代码验证）

- `adapter.ts`：Messages API 适配
- `files-api.ts` / `file-store.ts`：文件上传（图片）
- `images.ts` / `image-tokens.ts`：图片 token 估算
- `host.ts`：API host 配置
- `defaults.ts`：默认模型/参数

### 装配（entries.yml）

```yaml
- id: llm-deepseek
  name: '@deepseek-ai/dsh-llm-deepseek-api-key'
  config:
    apiKeyEnv: DEEPSEEK_API_KEY
    defaultContextWindow: 1000000
    streamIdleTimeoutMs: 172800000
```

### DSH 0.2.2 的变更（决策依据）

| 变更 | 决策含义 |
|---|---|
| `feat(llm): allow plugins to prepare pi-ai request headers` | 插件能**改请求头**——模型适配层可以直接用（比如加自定义 header、trace id） |
| `fix(llm-pi-ai): offload old images when a request exceeds the image-count bound` | 图片超 50 张自动省略最老的——**请求不失败** |
| `llm-request-purpose-declarations`：`purpose` 由 `LlmRequestPurposeMap` 派生 | 辅助请求（压缩、标题）必须**声明用途**，不能凭空传字符串 |

**dshiunx 的决策**：
- 请求头：跟进（插件化请求头的入口）
- 图片 offload：跟进（当前 `compaction-image-offload` 是 token 预算触发，DSH 是**数量**触发，两个维度）
- 用途声明：跟进（`compaction-basic` 要 import 自己的声明）

## 边界

- **模型层不做重试**：重试是 `llm-retry`
- **模型层不做压缩**：压缩是 `compaction-*`
- **模型层不读配置**：API Key 走环境变量

## 如何验证自己做对了

- 换一个 provider（比如加 `dsh-llm-openai`），Agent 循环不用改
- 不设 API Key 时启动，报错信息清楚（不是崩溃）
- 流式响应能逐块到达（`text-delta`）
- `ls packages/dsh-llm/src` 能看到 message/content/stream/assembler 的分离
- 人看：`dsh-llm` 的接口是否只有"发消息 → 收流"
