# 工具

**父级**：[插件模块](../插件模块.md)

## 要做什么

提供工具的注册表、执行管线，以及一组面向模型的工具（文件、搜索、Bash、子代理、待办、目标、技能、LSP、工作目录）。

## 为什么要做

工具是智能体"能做什么"的边界。工具必须是插件：能加、能删、能换实现，否则智能体就被锁死在固定能力里。

> 用户（2026-10-22，核心战略）：
> "其他的一切都可以插件化……加的所有东西都能进行精确管理控制优化还能随意创造。"

### 执行管线（代码验证）

`dsh-tools/src/index.ts` 定义两个事件：

| 事件 | 作用 |
|---|---|
| `tools/pre-execute` | 执行前决策（`PreToolDecision`） |
| `tools/execute` | 执行（可改写参数/结果） |
| `tools/post-execute` | 执行后 |
| `tools/result` | 结果发布 |
| `tools/change` | 工具注册表变更 |
| `tools/ptc-dispatch-log` | PTC 调度日志 |

```
模型发起 tool_call
  → tools/pre-execute（决策：允许/拒绝/改写）
  → 超时策略
  → 工具实现
  → 结果写回 session
```

### 工具声明的结构（代码验证）

每个工具有两个 name：
- `tool:xxx`（内部注册名）
- `xxx`（模型可见名）

参数用 `schemastery` / JSON Schema 描述（`json-schema.ts` 做校验）。

### PTC（programmatic tool calling）

`dsh-tools` 支持把工具 schema 渲染成 Python/TypeScript 代码（`ptc.ts`、`py-types.ts`、`ts-types.ts`），让模型写程序调用工具，而不是逐个调用。

## 边界

- **工具不直接读文件系统**：走 `ctx.fs` 服务（`dsh-fs-local`）
- **工具不直接起进程**：走 `ctx.subprocess` / `ctx.terminal`
- **工具不做审批**：dshiunx 无审批

## 如何验证自己做对了

- 加一个新工具包，entries.yml 加一行，模型就能用
- 删掉 `tool-fs`，其他工具不受影响
- 监听 `tools/execute` 能改写工具参数
- `grep -rn "name: '" packages/dsh-tool-*/src/*.ts` 能看到所有工具名
- 人看：每个工具包是否只有"参数 schema + 执行函数"
