# 装配

**父级**：[核心战略](../核心战略.md)

## 要做什么

用一份 YAML 决定"这台 dshiunx 装哪些插件、怎么配"——装配与代码分离，换组合不改入口。

## 为什么要做

如果装配写死在入口代码里，每换一个 provider、每加一个工具都要改代码。YAML 让"装配"成为配置，不是代码。

> 用户（2026-10-22）：
> "装配：entries.yml / profile / preset——全部是插件。"

## 怎么做

### 入口（代码验证）

`bin/headless.ts`：

```ts
const entries = yaml.load(readFileSync('packages/bundle-arch/entries.yml', 'utf8'))
const ctx = new Context()
await ctx.plugin(Loader)
for (const entry of entries) {
  await ctx.loader.create({ id: entry.id, name: entry.name, config: entry.config })
}
await ctx.loader.await()
```

### 装配原则

- **Arch 特化**：无 pwsh、无 Web UI、无遥测、无账户
- **最小可跑**：当前 51 条能完成一次完整对话（含工具、目标、技能、子代理）
- **可替换**：换 provider = 换 `llm-*` 条目

## 边界

- **装配不做版本检查**：插件版本由 npm 管
- **装配不做依赖排序**：顺序由 YAML 保证
- **不做 profile 切换**：当前只有 `bundle-arch` 一套（`profiles/` 未落地）

## 如何验证自己做对了

- 只改 entries.yml，`headless.ts` 不用动
- 删掉 `compaction-basic`，对话仍能跑（只是不压缩）
- 加一条 `dsh-tool-*`，模型立刻多一个工具
- `grep -c "^- id:" packages/bundle-arch/entries.yml` = 51
- 人看：entries.yml 是否能一眼看出"这台机器装了什么"
