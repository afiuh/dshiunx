# 插件模块

**父级**：[核心战略](../核心战略.md)

## 要做什么

把除了内核机制之外的一切都做成插件：Agent 循环、工具、会话、上下文管理、模型适配、终端、沙箱、技能、子代理——共 76 个 `dsh-*` 包。

## 为什么要做

"一切皆插件"不是口号：只有把 TUI、Agent 循环、工具都做成插件，才能替换、才能裁剪、才能让 AI 在运行时改造系统。

> 用户（2026-10-22，核心战略）：
> "其他的一切都可以插件化……在这个框架上加的所有东西都能进行精确管理控制优化还能随意创造。"

### 相比 DSH 裁掉了什么（代码验证）

DSH 的 `packages/` 有 58 个目录（含子包），dshiunx 没有的：

| DSH 有 | dshiunx | 原因 |
|---|---|---|
| `client` / `web` / `client-modules` | ❌ | 产品包袱（Web UI） |
| `browser-use` / `computer-use` / `cua` | ❌ | 产品功能 |
| `credentials` / `account` | ❌ | 账户体系 |
| `attachment` / `deliverables` | ❌ | 产品功能 |
| `acp` | ❌ | 客户端协议 |
| `boot` | ❌ | 用 `bin/headless.ts` 替代 |

> 用户（2026-11-07，DSH 表单）：
> "只保留能力，尽最大可能减少能力以外的东西对插件运行的限制：版本元数据、审批流程、平台假设、产品形态。"

### 插件之间怎么协作

- 通过 **服务**：`ctx.get('sessions')`、`ctx.get('tools')`、`ctx.get('agents')`
- 通过 **事件**：`tools/execute`、`session/event`、`agent/pre-step`
- **不直接 import 彼此**（除了类型）

### 去版本化（2026-11-07 落地）

**决策**（D39，2026-10-22）：结构契约是事实——能 `inject`/`provide`/`apply` 就是合法插件，不检查版本。

**落地**：85 个包的 `package.json` 删除 `version`、`dependencies`、`peerDependencies`、`devDependencies`、`files`、`scripts`、`engines`、`publishConfig`，只保留 `name`、`type`、`main`、`types`、`exports`。

**为什么**：版本号是预判，会阻止本来能工作的组合；依赖由源码 import 决定，不由 package.json 决定。

## 边界

- **插件不知道内核之外的东西**：每个插件只依赖它 inject 的服务
- **插件可以互相替换**：模型适配器、压缩策略、工具实现都能换
- **插件不做产品假设**：没有"默认界面""默认流程"

## 如何验证自己做对了

- 任意一个插件删掉，其余插件仍能启动（除非有硬依赖）
- 换一个模型适配器（`dsh-llm-*`），Agent 循环不用改
- 换一个压缩策略（`compaction-*`），会话不用改
- `ls packages/*/package.json | wc -l` = 90（全部有源码）
- 人看：`packages/` 下每个包是否只有一个职责
