# 插件模块

**父级**：[核心战略](../核心战略.md)

## 这个模块负责什么

把插件体系做自由、可组合、可自进化：定义插件怎么存在、怎么分类、怎么装配、怎么演化。

## 这一级拆成哪几个子模块

| 子模块 | 负责什么 |
|---|---|
| [插件规范](./插件规范/README.md) | 一个插件必须是什么样：manifest、生命周期契约、服务契约、配置 schema、隔离边界 |
| [插件分类](./插件分类/README.md) | 插件按什么维度分类（运行时 / 界面 / 工具 / 用户 / 装配），每类的边界和契约 |
| [插件装配](./插件装配/README.md) | 插件怎么组合成系统：profile、entries、按需加载、裁剪、预设 |
| [插件演化](./插件演化/README.md) | 插件怎么自我演化：AI 写插件、运行时注册、热加载、回滚、观测 |

## 这一级不回答的问题

- 每个子模块内部怎么实现 → 子模块自己的 `README.md`
- 具体某个插件（fs / bash / TUI / agent-loop）怎么做 → 各自插件目录
- 内核机制怎么实现 → [内核模块](../内核模块/README.md)

## 硬约束

- 插件不依赖具体内核实现，只依赖内核契约
- 插件可以无限嵌套，每层拥有同样的内核能力（见[核心战略 P3](../核心战略.md)）
- 淘汰的插件/决策直接删除，git 记录原因
