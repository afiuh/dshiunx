# 插件化

**父级**：[TUI 插件](../TUI插件.md)

## 为什么需要

TUI 插件化的本质和路径。

## 准备怎么实现

### 宏观想法

插件化的本质 = **重写屏幕**（`ChatView` + 组件分层），不是拆 `Chat`。

```
单体屏幕 → ChatView + 组件组合
```

**为什么**：`Chat` 从设计上就是单体屏幕；拆是死路，换架构才是出路。

### 细节实现
## 决策（06 归档）

| 决策 | 内容 |
|---|---|
| **`tui-chat` 已解耦** | 用 `tuiChatProps` 构建 `Chat`（`channel` 从 `ctx.get('tuiChatProps').channel` 拿） |
| **插件化的本质** | **重写屏幕**（`ChatView` + 组件分层），不是“拆 `Chat`” |
| **`Chat` 是单体屏幕** | 从设计上就是单体——插件化需要**换架构**（屏幕 → 组件组合） |
| **已解耦插件** | `tui-protocol` / `tui-chat` / `tui-status` + 6 个模块边界 |

## 路径

1. **重写屏幕**（`ChatView` + 组件分层）
2. **组件库**（118 个组件）
3. **逻辑插件**（6 个函数）
4. **渲染插件**（664 行）
