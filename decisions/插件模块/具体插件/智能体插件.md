# 智能体插件

**父级**：[具体插件](../具体插件.md)

## 为什么需要

系统"怎么想"由这里决定：循环怎么推进、提示怎么装配、用哪个模型、扮演什么角色、子代理怎么分工。

## 准备怎么实现

### 宏观想法

按"一个智能体由什么组成"拆：

```
智能体插件
├── agent          实例管理：创建/恢复/注册
├── agent-loop     循环：turn 驱动、初始化/销毁
├── model-selection 选择：持久化投影、lastUsed/pending
├── system-prompt  提示装配：段、上下文、变量、呈现瀑布
├── preset         预设：一组插件的组合（四模式）
├── persona        角色：前缀/后缀
├── agent-instructions  项目指令：AGENTS.md 的发现/渲染/截断
├── default-model  默认模型配置
├── tool-presentation   工具呈现配置
└── subagent       子代理：目录、激活、子上下文
```

**为什么按"组成"拆而不是按包拆**：包是发布单位，节点是功能单位。一个功能可能跨包（如 preset 含 `agent-preset` + `agent-preset-registry`）。

### 边界

| 属于智能体插件 | 不属于 |
|---|---|
| 决定"怎么想"的逻辑 | 工具怎么执行（工具插件） |
| 提示内容与装配顺序 | 模型协议转换（运行时基础/模型） |
| 预设组合 | 会话事件存储（运行时基础/会话） |

- 删掉任一子节点，其余智能体功能仍可用
- 智能体插件不依赖界面
- 换循环（agent-loop）不改 agent 服务调用方
