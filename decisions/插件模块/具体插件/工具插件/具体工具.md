# 具体工具

**父级**：[工具插件](./工具插件.md)

## 为什么需要

执行器决定"怎么执行"，具体工具决定"能做什么"。每个工具职责单一，才能独立启停、替换、组合。

## 准备怎么实现

### 宏观想法

每个工具是一个独立插件：声明 `ToolDefinition`（名称 / schema / 描述 / 执行函数），注册到 `ctx.tools`，由 preset 决定可见性。

**为什么一个工具一个包**：启停粒度 = 能力粒度。关掉 `web` 不该影响 `bash`；换掉 `fs` 的实现不该动其他工具。

### 边界

| 工具插件负责 | 工具插件不负责 |
|---|---|
| 工具的输入/输出 schema | 执行顺序与并发（执行器） |
| 工具的执行函数 | 工具的可见性（preset） |
| 对服务的依赖声明（`inject`） | 服务本身的实现 |
| 工具描述（给模型看的文本） | 呈现（presentation 由执行器/系统提示处理） |

**硬约束**：工具只依赖服务（`ctx.fs` / `ctx.subprocess` / `ctx.lsp` / `ctx.web`），不直接 import 其他工具。

### 分类（按能力，不按实现）

**只列"注册工具"的包**（`defineTool` / `ctx.tools.register`）。服务与运行时不属于本节点。

| 类别 | 包 | 工具 |
|---|---|---|
| 文件 | `tool-fs` / `tool-fs-search` / `tool-working-directory` | `read` / `write` / `edit` / `read_image`、`glob` / `grep`、`working_directory` |
| 命令 | `tool-bash` / `tool-bash-persistent` | `bash`（一次性 / 持久 shell） |
| 协作 | `tool-subagent` / `tool-subagent-control` / `tool-ask-user` / `tool-goal` / `tool-todo` / `tool-schedule` | `list_subagent_models`、`send_message` / `interrupt_agent` / `list_agents`、`ask_user_question`、`goal_*`、`todo_write`、`schedule_*` |
| 能力 | `tool-lsp` / `tool-skill` / `tool-web` / `tool-workflow` / `tool-jobs` / `tool-present` | `lsp`、`skill`、`web_fetch` / `web_search`、workflow、`job_*`、`present` |
| 检视 | `tool-cordis` | `cordis_inspect_*`（只读运行时 API 检视） |
| 集成 | `mcp-client` / `mcp-resources` | MCP 工具、`list_mcp_resources` / `read_mcp_resource` |
| 模式/管理 | `plan-mode` / `plugin-manager` | `plan`、`plugin_manager` |

**容易误归的两个**：

| 包 | 实际是什么 | 归属 |
|---|---|---|
| `tool-call-timeout-policy` | 工具调用的超时**包装策略**（工具声明 `timeoutMs`，它负责计时并映射为 `TOOL_TIMEOUT`），本身不注册工具 | 执行器的配套策略，不是具体工具 |
| `subagent` | 子代理**服务**；`structured.ts` 注册的是子上下文内部的工具（`childCtx.tools.register`），不是顶层工具 | 智能体插件（服务），不是具体工具 |

### 验证

- 删除任一工具包，其余工具照常注册与执行
- 每个工具都有 schema、描述、执行函数三件套
- 工具不 import 其他工具，只 import 服务接口
