# 插件演化

**父级**：[插件基础设施](../插件基础设施.md)

## 为什么需要

插件怎么自我演化：AI 写插件、运行时注册、热加载、回滚、观测。

## 准备怎么实现

### 宏观想法

插件演化：AI 写插件 / 运行时注册 / 热加载 / 回滚 / 观测——**AI 是内核的一部分**（P6）。

```
写 → 注册 → 热更 → 回滚
```

**为什么 AI 写插件**：自进化（P6）——AI 能在运行时改造系统，不用等人写代码。

### 细节实现

1. **AI 写插件**：按插件规范（ESM / 静态 import / effect 清理 / 状态外置 / 入口声明），风险控制见 [AI插件风险控制](../插件规范/AI插件风险控制.md)。
2. **运行时注册**：`ctx.loader.create()` / `ctx.plugin()`；动态插件通过 loader 挂载（可热加载）。
3. **热加载**：HMR（`cordis-plugin-hmr`），任意插件层可热更；限制见 [热更新](../../../内核模块/热更新/热更新.md)。
4. **回滚**：git 每步提交，出问题 `git revert`。
5. **观测**：`ctx.logger` + 心跳 + watchdog（死循环处理）。
6. **第三方适配**：复制到 `profiles/`，依赖改 workspace；适配器（adapt-plugin）后置（历史决策）。
7. **worker / 子进程**：可选形态（按需），不是默认。

## 演化闭环

```
AI 写插件 → 规范检查 → 加载前测试 → 运行时监控 → 出问题回滚
```

## 边界

| | 插件演化（本模块） | 插件装配 |
|---|---|---|
| 管什么 | 插件怎么改/加/回滚 | 插件怎么组合 |
| 关键动作 | 写/注册/热更/回滚 | profile/bundle/entries |

## 硬约束

- 每步 git 提交（可回滚）
- AI 写的插件必须过风险控制四阶段
- 热加载不改变服务契约（只换实现）

## 参考什么

`packages/cordis-plugin-hmr/src/`、`packages/cordis-plugin-loader/src/`、`scripts/`

## 边界

| 演化管 | 不管 |
|---|---|
| 插件**从哪来、怎么进来**（安装/来源） | 插件进来后怎么组合（[插件装配](../插件装配/插件装配.md)） |
| 插件**怎么启停**（启用/禁用/删除） | 插件怎么启动（[启动链路](../启动链路/启动链路.md)） |
| 插件**怎么改**（AI 写、热更、回滚） | 插件长什么样（[插件规范](../插件规范/插件规范.md)） |
| 插件**怎么被观察**（日志/心跳/watchdog） | 运行时的资源管理（[运行时支撑](../运行时基础/运行时支撑/运行时支撑.md)） |

**明确不做**：版本管理（`listVersions` / `updateBundle` / `updatable` / exemption）——违反 P7，见 [插件模块](../../插件模块.md) 排除清单。

## 验证

- 装一个插件只需 spec（包名/路径/URL），不需要版本约束
- 启用/禁用只改 profile patch 的 `disabled`，不重新安装
- AI 写的插件经过风险控制四阶段（见 [AI插件风险控制](../插件规范/AI插件风险控制.md)）
- 热更失败能回滚到上一个提交（`git revert`）
- 观测能回答"哪个插件卡住/多久没输出"
