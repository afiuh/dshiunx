# 插件演化

**父级**：[插件基础设施](../插件基础设施.md)

## 负责什么

插件怎么自我演化：AI 写插件、运行时注册、热加载、回滚、观测。

## 相关源码

`packages/cordis-plugin-hmr/src/`、`packages/cordis-plugin-loader/src/`、`scripts/`

## 决策

1. **AI 写插件**：按插件规范（ESM / 静态 import / effect 清理 / 状态外置 / 入口声明），风险控制见 [AI插件风险控制](../插件规范/AI插件风险控制.md)。
2. **运行时注册**：`ctx.loader.create()` / `ctx.plugin()`；动态插件通过 loader 挂载（可热加载）。
3. **热加载**：HMR（`cordis-plugin-hmr`），任意插件层可热更；限制见 [热更新](../../../内核模块/热更新/热更新.md)。
4. **回滚**：git 每步提交，出问题 `git revert`。
5. **观测**：`ctx.logger` + 心跳 + watchdog（死循环处理）。
6. **第三方适配**：复制到 `profiles/`，依赖改 workspace；适配器（adapt-plugin）后置（历史决策）。
7. **worker / 子进程**：可选形态（按需），不是默认。

## 演化闭环

```
AI 写插件 → 规范检查 → 加载前测试 → 运行时监控 → 出问题回滚
```

## 边界

| | 插件演化（本模块） | 插件装配 |
|---|---|---|
| 管什么 | 插件怎么改/加/回滚 | 插件怎么组合 |
| 关键动作 | 写/注册/热更/回滚 | profile/bundle/entries |

## 硬约束

- 每步 git 提交（可回滚）
- AI 写的插件必须过风险控制四阶段
- 热加载不改变服务契约（只换实现）
