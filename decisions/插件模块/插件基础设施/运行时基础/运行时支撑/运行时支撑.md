# 运行时支撑

**父级**：[运行时基础](../运行时基础.md)

## 为什么需要

工具要起进程、要读写文件、要跑沙箱、要压缩长结果。这些不是"能力"，是能力执行时的底座。

## 准备怎么实现

### 宏观想法

| 服务 | 提供什么 | 谁用 |
|---|---|---|
| `subprocess` | 子进程生命周期、输出捕获、终止 | `tool-bash` / PTC 运行时 / 插件安装 |
| `sandbox` | 执行策略（文件/网络/进程权限） | 子进程、工具执行 |
| `attachment` | 大对象暂存（图片、长文本） | 工具结果、会话 |
| `jobs` | 后台任务（长跑命令） | `tool-bash` / `tool-jobs` |
| `compaction` | 长上下文压缩策略 | 会话使用方 |

**共同点**：它们管理**资源**（进程、文件、内存），不管理**语义**（做什么）。

### 边界

| 运行时支撑负责 | 不负责 |
|---|---|
| 资源的创建/回收/限额 | 资源用来做什么（工具） |
| 失败分类（超时/权限/磁盘） | 失败后怎么向模型解释（工具/呈现） |
| 跨平台差异（POSIX / Windows） | 业务策略 |

### 验证

- 子进程超时后整棵进程树被终止（不留孤儿）
- 沙箱拒绝时返回结构化错误，不是崩溃
- 附件超过阈值时转存，不撑爆会话
