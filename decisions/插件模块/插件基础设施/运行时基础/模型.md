# 模型

**父级**：[运行时基础](./运行时基础.md)

## 为什么需要

智能体本身不会说话——它通过模型适配器把"会话 + 工具定义 + 系统提示"变成一次请求，再把响应变回事件。

## 准备怎么实现

### 宏观想法

```
智能体 → llm 服务（路由）→ 适配器（provider）→ 外部 API
                                    ↓
                              计量（token）/ 重试 / 错误分类
```

- **路由按 provider + model**：适配器注册自己支持的 provider
- **适配器隔离协议差异**：上游 API 的形状只在适配器里
- **计量独立**：token 统计不进入请求路径，作为投影/旁路

### 边界

| 模型负责 | 不负责 |
|---|---|
| 请求/响应的协议转换 | 提示词内容（智能体） |
| 路由与回退 | 工具定义（工具插件） |
| 流式输出的组装 | 会话写入（智能体） |
| token 计量、重试、错误分类 | 成本策略（使用方） |

### 计量的状态设计（rc.3 结构改进）

**变更**：计量从"服务内存状态"改为"固定大小的投影"（`measurement-projection.ts`）。

| 字段 | 含义 | 大小 |
|---|---|---|
| `headerSeq` | 一个 header 引用 | 固定 |
| `stepStart` | 一个打开的 step（turn/step） | 固定 |
| `anchor` | 最近一次成功调用的 usage 事实 | 固定 |
| `invalidSeq` | 失效游标 | 固定 |

**为什么固定大小**：投影要能从事件流恢复。如果状态里存"每次请求的 usage 列表"，它会随会话线性增长，恢复成本也线性增长。只保留"一个 header + 一个 step + 一个锚点"，恢复时从锚点往后折叠即可。

**两条分工**：
- **固定事实**（上面的四个字段）：进投影，可恢复
- **位置化附件价格**：可重建缓存——按事件位置重新计算，不进入固定状态

**纯函数**：`advanceMeasurement(state, event)` 返回新状态，不修改前一个状态（可重放）。

**我们的现状**：`dsh-token-meter` 有 `breakdown-projection` / `usage-projection`，计量逻辑仍在 `TokenMeter` 服务里（内存），没有 `measurement-projection`。

### 验证

- 换适配器（DeepSeek → 其他）不改智能体代码
- 流式响应中断时，已产出的内容不丢
- 计量可从事件流重建（不依赖内存计数）
