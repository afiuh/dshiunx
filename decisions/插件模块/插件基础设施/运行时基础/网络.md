# 网络

**父级**：[运行时基础](../运行时基础.md)

## 为什么需要

工具要抓网页、要搜索；未来可能有浏览器、下载器。联网能力不该写死在某个工具里。

## 准备怎么实现

### 宏观想法

```
工具（web_fetch / web_search）→ ctx.web（服务）→ provider（fetch / search）
                                              ↓
                                     能力探测（ready?）
```

- **服务与工具分离**：`ctx.web` 提供能力，`tool-web` 把它包装成模型可调用的工具
- **provider 可替换**：抓取（HTTP）与搜索（各家 API）各自注册
- **能力探测**：provider 不可认证时，工具对模型不可见（而不是调用时报错）

### 边界

| 网络负责 | 不负责 |
|---|---|
| HTTP 抓取（重定向、大小/时间限制、编码） | 内容怎么给模型看（工具/呈现） |
| 搜索 provider 的调用与结果归一 | 搜索策略（工具） |
| 代理、证书、认证配置 | 用户审批（工具执行链） |
| 能力探测（`searchReady` / `fetchReady`） | 工具可见性（preset） |

### 验证

- 换搜索 provider 不改 `tool-web`
- provider 不可用时，工具不出现在模型可见列表里
- 抓取只跟随同源重定向，不携带浏览器 cookie
