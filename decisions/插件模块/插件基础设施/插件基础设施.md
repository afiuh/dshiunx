# 插件基础设施

**父级**：[插件模块](../插件模块.md)

## 为什么需要

插件要"自由、可组合、可自进化"，需要两样东西：

1. **管理机制**：插件长什么样、怎么分类、怎么装配、怎么演化、怎么启动
2. **运行时地基**：插件跑起来依赖的通用服务（会话、模型、网络、运行时支撑）

少了第一样，插件没有规则；少了第二样，插件没有地基。

## 准备怎么实现

### 宏观想法

```
插件基础设施
├── 管理（怎么管插件）
│   ├── 插件规范 / 插件分类 / 插件装配 / 插件演化 / 启动链路
└── 运行时基础（插件跑在什么上面）
    ├── 会话 / 模型 / 网络 / 运行时支撑
```

**为什么运行时基础归这里而不是"具体插件"**：判断标准是"被用还是在用"。
- 会话/模型/网络/运行时支撑 → **被**智能体、工具、界面使用
- 智能体/工具/界面 → **在**使用它们，提供具体能力

### 边界

| 属于插件基础设施 | 属于具体插件 |
|---|---|
| 插件的规则与装配方式 | 插件本身提供的能力 |
| 被多数插件依赖的通用服务 | 决定"做什么"的逻辑 |
| 服务契约与资源生命周期 | 业务策略与呈现 |

### 子节点

**管理**

| 子节点 | 负责什么 |
|---|---|
| [插件规范](./插件规范/插件规范.md) | 插件形态、manifest、生命周期、服务契约、执行器也是插件 |
| [插件分类](./插件分类/插件分类.md) | 按什么维度分类、catalog 怎么生成 |
| [插件装配](./插件装配/插件装配.md) | profile / bundle / preset / 按需加载 |
| [插件演化](./插件演化/插件演化.md) | 来源与安装、启停与版本、AI 写插件、热加载回滚 |
| [启动链路](./启动链路/启动链路.md) | boot 五步、必需项分级、StartupError |

**运行时基础**

| 子节点 | 负责什么 |
|---|---|
| [运行时基础](./运行时基础/运行时基础.md) | 会话 / 模型 / 网络 / 运行时支撑 的总边界 |

### 验证

- 只装管理基础设施，系统能启动但没有能力（空壳）
- 只装运行时基础，插件有地基但没有规则
- 两者都不依赖任何具体插件
