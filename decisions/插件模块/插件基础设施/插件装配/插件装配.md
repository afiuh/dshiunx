# 插件装配

**父级**：[插件基础设施](../插件基础设施.md)

## 为什么需要

插件怎么组合成系统：profile、entries、按需加载、裁剪、预设。

## 准备怎么实现

### 宏观想法

插件装配：profile + bundles + entries（分层 + 索引）。

```
profile.yml → bundles → entries.yml
```

### 细节实现
## 决策

1. **profile**：第一版一个 `profiles/default/`（历史决策）。
2. **entries.yml**：配置树，所有插件通过 Include 挂载（统一挂载）。
3. **按需加载**：`disabled` 条件（`!!js` 表达式）+ loader 的 `create` / `remove`。
4. **裁剪**：不需要的插件直接删（entries 条目），不留 disabled。
5. **预设**：preset（Standard / PTC / Minimal / Creator）是“插件组合的预设”，通过 `agent-preset` 挂载。
6. **启动链路**：见 [启动链路](../启动链路/启动链路.md)。

## 与 DSH 的差异：装配方式（详细对比）

### DSH：bundle / patch 分层

```
base bundle (cordis.patch.yml)
  → web-app bundle (patch)
    → preset patch (standard / ptc / minimal / cordis)
      → user patch (profile/cordis.patch.yml)
```

- 每层是 patch（`insert` / 覆盖 / `disabled`）
- 最终配置 = 所有 patch 叠加
- 可以 dump 出最终 entries

### 我们：单一 entries.yml

```
entries.yml（所有插件 + preset 配置）
```

- 一个文件，直接挂载
- 没有分层

### 对比

| 维度 | DSH（bundle/patch） | 我们（单一 entries.yml） |
|---|---|---|
| 配置集中度 | 分散（多文件） | **集中（一个文件）** |
| 分层 / 复用 | ✅ 可以组合 bundle | ❌ 复制整个文件 |
| 覆盖 / 裁剪 | ✅ patch 按 id 覆盖 | ⚠️ 手动改 |
| 调试 | ⚠️ 需要 dump 最终配置 | ✅ 直接看文件 |
| 多产品 | ✅ 同一 bundle 组合不同产品 | ❌ 每个产品复制 / 改 |
| 插件市场 | ✅ bundle 可发布 | ❌ 无 |
| 根级服务位置 | ✅ 天然正确（base 顶层） | ⚠️ preset registry 在 entry 层 |

### 判断

**短期（单产品）**：我们的简单，够用。
**长期（多产品 / 插件市场 / 自进化）**：DSH 的分层更合适。

**但两者可以结合**：用“生成”机制——

- 源：base / preset / user 分层
- 生成：`entries.yml`（单一文件）
- 好处：保留简单性 + 分层能力

### 改进方案：分层 + 集中索引（用户提出）

**思路**：采用 DSH 的分层（bundle/patch），但加一个“集中索引”文件——两者兼顾。

```
catalog.yml          ← 集中索引：所有插件（id / name / 类别 / 来源）
bundles/
├── base/            ← 基础层（运行时 + 工具）
├── web-app/         ← Web 层（未来）
└── presets/         ← preset 层（standard / ptc / minimal / creator）
profiles/
└── default/         ← 发行版：选择哪些 bundle
```

| 文件 | 职责 |
|---|---|
| `catalog.yml` | **索引**：有哪些插件、属于哪类、来源；不是最终配置 |
| `bundles/*` | **分层 patch**：每层插入/覆盖插件（DSH 式） |
| `profiles/*` | **发行版**：选择 bundle 组合（像 Arch 的不同发行版） |
| 生成器（可选） | `catalog + bundles + profile → entries.yml` |

**与 DSH 的差异**：DSH 只有 bundle/patch，没有集中索引；我们加 `catalog.yml`——可查、可组合、可生成。

**发行版类比**：
- Arch：内核 + 包管理，不同发行版（Manjaro / EndeavourOS）选择不同预装
- 我们：内核 + 插件，不同 profile 选择不同 bundle 组合

**可行性**：可行。`applyEntryPatches` 已支持 patch 叠加；`catalog.yml` 只是索引，不参与运行时；生成器可选（loader 也可以直接应用 patch）。

### 实施状态（2026-10-23）

✅ **已完成**：

```
bundles/
├── base/cordis.patch.yml          ← 运行时 + 工具
├── presets/{standard,ptc,minimal,creator}/cordis.patch.yml
└── tui/cordis.patch.yml           ← 界面
profiles/default/profile.yml       ← bundle 组合
scripts/build-entries.mjs          ← profile + bundles → entries.yml（diff 0）
scripts/gen-catalog.mjs            ← entries.yml → catalog.yml
```

| 命令 | 作用 |
|---|---|
| `npm run build:entries` | 组合 bundles → entries.yml |
| `npm run catalog` | build:entries + 生成 catalog.yml |

**发行版** = 不同 `profile.yml` 选择不同 bundle 组合。
