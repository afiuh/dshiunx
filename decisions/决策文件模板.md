# 决策文件模板（内容结构 + 精细度标准）

**父级**：[决策网络](./决策网络.md) · **配套**：[AI行为约束.md](./AI行为约束.md)
**用途**：写任何决策文件前先看本文。**结构错 / 写得简略 = 全部重来**，所以模板必须提前定死。
**来源**：内核 42 文件验证后的正例（`监听与防抖.md`）与反例（`Isolate.md` 修 4 轮）

---

## 一、文件骨架（六节，缺一节不算完成）

```markdown
# <模块名>

**父级**：[<上层模块>](<相对路径>)

## 为什么需要

<从上层拆下来的动机：这个实现解决上层的哪个问题。1~3 句，必须能追溯到父级文件。>

## 准备怎么实现

### 宏观想法

<一句话概括 + 流程框图 + **为什么这样设计** + 关键取舍>

```
输入 → 步骤 A → 分支 → 步骤 B → 输出
```

**为什么这样**：<选这个结构的理由；如果有别的结构，为什么不选>

### 细节实现

1. **<决策标题>**：<行为描述>
   - 源码：`<文件>:<行号>`（<函数/类>）
   - 为什么：<设计理由>
   - 不选：<备选方案> → <否决理由>（无备选写"无"）
   - 边界：<默认值 / 空值 / 异常 / 并发 / 超时>

2. ...

## 参考什么

- 源码：`packages/<包>/src/<文件>:<行号>`
- DSH 对照：<差异点或"一致">
- 库/文档：<外部依据>
- 归档：<历史讨论路径，如有>

## 与 DSH 的差异（可选，有差异才写）

<逐条列出：我们改了什么、为什么改、影响面>
```

## 二、每条决策的五要素（缺一即"简略"）

| 要素 | 要求 | 反例（不算） |
|---|---|---|
| **① 行为** | 可执行描述：谁在什么条件下做什么，产出什么 | "负责加载插件"（太虚） |
| **② 源码** | `文件:行号` + 函数/类名，打开确认过 | 只写包名；行号是猜的 |
| **③ 为什么** | 设计理由，能推出这个选择 | "这样比较好" |
| **④ 不选** | 备选方案 + 否决理由（无备选写"无"） | 完全不提替代方案 |
| **⑤ 边界** | 默认值 / 空值 / 异常 / 并发 / 超时，至少写 1 项 | 只写正常路径 |

**判定**：一条决策如果删掉 ③④⑤ 后读者仍能"知道有这么回事"，但**不能判断对错**——就是简略。

---

## 三、宏观想法的三条硬要求

1. **必须有框图**（ASCII 即可）：能看出输入 → 中间步骤 → 分支 → 输出
2. **必须写"为什么这样"**：不是复述框图，而是解释结构选择的理由
3. **有替代结构时必须写"为什么不选"**：例如"为什么用抽象类而不是接口 + 组合"

---

## 四、精细度红线（出现任一条 = 不合格）

| # | 红线 | 为什么 |
|---|---|---|
| 1 | 细节条目 < 5 条（源码 > 500 行的模块） | 覆盖不全 |
| 2 | 任一条目缺源码行号 | 无法核对 |
| 3 | 只写正常路径，无边界/异常 | 行为级验证过不了 |
| 4 | 宏观想法无框图 | 结构说不清 |
| 5 | 写"是什么"（源码翻译）而非"为什么" | 变成说明书 |
| 6 | 复制旧文件内容不核对源码 | 旧文件可能是错的 |
| 7 | 决策条目之间重复讲同一件事 | 说明没拆清（Isolate 反例） |
| 8 | 规划项没标"规划，无源码" | 读者以为是实现 |

**长度参考**（不是硬指标，是结果）：
- 源码 300~800 行 → 文件 60~100 行，决策 5~9 条
- 源码 800~2000 行 → 文件 100~160 行，决策 9~14 条
- 源码 > 2000 行 → **先拆文件**，单文件不超过 2000 行源码

## 五、正例 / 反例（来自内核）

### 正例：`内核模块/热更新/实现拆分/监听与防抖.md`（47 行，9 条）

好在哪里：
- 第 4 条把 `change` 事件的 **4 个分支**全列出来，每个带行号
- 第 7 条写"为什么用 timer 服务"：`setTimeout` 不随 fiber dispose 清理 → 这是**为什么**，不是**是什么**
- 第 8 条写默认值 + **DSH 原版没有默认值会导致 chokidar 报错** → 边界 + 差异
- 第 9 条写"为什么不展开 `...this.config`" → **不选什么**

### 反例：`内核模块/嵌套与隔离/实现拆分/Isolate.md`（35 行，修 4 轮）

问题：
- 第 1 条和第 4 条讲同一件事（两层 label），说明第一次没拆清
- 第 4 条是"补丁式"追加（"容易混淆"），不是设计决策
- 缺"与 DSH 差异"节

## 六、插件模块的额外要求（源码量大）

插件模块涉及 42 个包 / 约 54,000 行，比内核复杂，所以：

1. **单文件对应源码上限 2,000 行**——超过就先拆文件（已在 `源码地图.md` 定好 50 个文件）
2. **通读范围必须列清单**：文件开头列出"本决策涉及源码"（文件 + 行数），读完逐个打勾
3. **跨包行为要写清边界**：例如"preset 挂载"涉及 `agent-preset-registry` + `cordis-plugin-loader` + `app-boot`，要写明谁调用谁
4. **生成物标注**：`dsh-tool-cordis/api-catalog.ts`（8,974 行）标"生成物，不分析内容"
5. **决策条数下限**：源码 500~1000 行 ≥ 6 条；1000~2000 行 ≥ 10 条

---

## 七、开工顺序（防止批量返工）

```
1. 读本模板 + AI行为约束
2. 选 1 个文件做样板（源码中等、有代表性）
3. 按模板写 → 交用户审
4. 用户确认结构/精细度 → 才批量
5. 批量时每文件仍走：通读 → 写 → 只看决策 → 只看代码 → 自检 → 提交
```

**禁止**：没经用户确认样板就批量写（结构错 → 50 个文件全返工）。
