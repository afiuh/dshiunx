# 决策文件标准

**父级**：[方法](../方法.md)

## 目的

定义"一个决策文件算完成"的标准，**一次做对**，避免反复（结构 → 精细度 → 源码对照 分开做会重来）。

## 一个文件算完成 = 三项全过

### 1. 结构完备

```markdown
# 文件名
**父级**：`[上层模块](../上层.md)`

## 为什么需要
（从上层拆下来的动机：这个实现解决上层哪个问题）

## 准备怎么实现

### 宏观想法
（一句话 + 流程框图 + **为什么这样做**）

### 细节实现
（逐条决策 + 源码行号/API）

## 参考什么
（源码/归档/DSH/库文档）
```

### 2. 宏观想法有"为什么"

不是概括流程，而是：
- **为什么这样设计**（从决策推导）
- **不选什么、为什么**（如果有其他方案）
- 规划类（无源码）要标注"规划，无源码"

### 3. 源码对照

- 每条决策 → 源码验证（行号/API/流程）
- 宏观想法的"为什么" → 源码注释/实现/归档依据
- 发现错误 → 修 → 提交

## 检查顺序（一次做完）

```
1. 读决策文件（现有内容）
2. 打开源码（相关文件）
3. 逐条对照（决策 → 源码）
4. 补结构（如果缺）
5. 补宏观想法（为什么）
6. 补细节（行号/API）
7. 更新清单（三项打勾）
8. 提交
```

## 清单

`源码对照清单.md` 每个文件三列：
- 结构（✅/⬜）
- 精细度（宏观想法 + 为什么）
- 源码（逐条对照）

**三项全 ✅ 才算完成。**
