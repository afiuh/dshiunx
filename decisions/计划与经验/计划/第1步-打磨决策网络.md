# 第1步-打磨决策网络

**父级**：[计划](./计划.md)

#
## 目标

让决策网络吸收 DSH rc.3 里对我们有用的功能优化，并据此修正已有决策。

## 子步

| 子步 | 做什么 | 产出 | 验收 |
|---|---|---|---|
| **1.1 筛选** | 从 6,360 文件变更里筛"功能优化"；排除 locale / 测试 / 文档 / 网站 / 产品包袱（Web UI、账户、遥测、市场 UI） | `计划/第1步/候选清单.md` | 每条候选有源码路径；排除项写明理由 |
| **1.2 详细研究** | 每个候选：① 完整读上游实现 ② 对照我们的决策 ③ 对照我们的源码 ④ 分析优劣 | `计划/第1步/分析-<模块>.md` | 判断必须引 P1/P6/P7；不得只写"上游更好" |
| **1.3 优化决策** | 按分析结果新增 / 修改 / 删除决策文件；冲突按核心战略裁决 | 更新的 `decisions/` | 决策与源码一致，或明确标"待改代码"；无 P7 违规 |
| **1.4 全局复查** | 用三层验证抽查改动过的文件 | 复查记录 | 自洽 / 行为 / 差异三层无 ❌ |

## 研究硬约束

| 约束 | 含义 |
|---|---|
| **P7 优先** | 版本检查、版本管理、兼容性门槛一律不吸收（`engines.dsh`、`updatable`、`listVersions`、`updateBundle`、version exemption、preflight） |
| **P1 最小内核** | 能被插件实现的能力不进内核（plugin-market 只能作为插件） |
| **P6 自进化** | 优先吸收"让系统更能自我改造"的结构（执行器插件化是典型） |
| **产品包袱不吸收** | Web UI、账户、遥测、客户端适配 |
