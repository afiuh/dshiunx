# 经验

**父级**：[计划与经验](../计划与经验.md)

## 为什么需要

同一个坑踩第二次，成本是第一次的两倍（第一次浪费的时间 + 第二次浪费的时间）。经验模块把踩过的坑写成**可执行的约束**，而不是故事。

**经验分两种来源**：
- **自己的**：AI 行为约束、补救方案（我们踩的坑）
- **别人的**：上游吸收（DSH 踩过/做对的，我们学或不学）

## 包含什么

| 文件 | 内容 | 维护方式 |
|---|---|---|
| [AI行为约束](./经验/AI行为约束.md) | 六条铁律 + 12 条失败模式档案 + 危险信号词典 + 违规处理 | **只增不改**：新坑补进档案，旧教训不删 |
| [补救方案](./经验/补救方案.md) | 决策网络"从代码反推文档"的根因与补救路径 | 改一次后归档为历史依据 |
| [上游吸收](./经验/上游吸收.md) | **别人的经验**：每次上游更新后，哪些值得学、哪些不能学 | 按版本积累（`rc3/`、`rc4/`…） |

## 维护规则

1. **只增**：已有教训不删除、不弱化（弱化等于遗忘）
2. **可执行**：每条经验必须能转成"遇到 X 时做 Y"，否则只是感慨
3. **带现场**：写清案发时间、当时怎么想的、实际后果（没有现场的经验会被当成空话）
4. **可推翻**：如果某条经验在实践中被证明过严或错误，在原文上标注"已被 X 取代"，不悄悄删掉
