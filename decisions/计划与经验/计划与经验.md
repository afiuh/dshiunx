# 计划与经验

**父级**：[核心战略](../核心战略.md)

## 为什么需要这个模块

核心战略是**动态**的：目标不变（最小内核 + 一切皆插件 + 自进化），但推进顺序、方法、踩过的坑一直在变。

如果没有这个模块，每次推进都要重新讨论"先做什么""上次为什么返工"，战略就变成一次性文档。所以把两类东西收进来：

| 子模块 | 回答什么 | 特点 |
|---|---|---|
| **计划** | 先做什么、后做什么、每步的验收 | **频繁更新**（每次情况变化就改） |
| **经验** | 踩过什么坑、怎么避免 | **只增不改**（教训不删除，只补充） |
| **方法** | 怎么写决策、怎么验证 | **可改**（发现更有效的方式就改） |

## 为什么不是"独立模块"

它不是业务模块（不产出功能），而是**战略的执行方式**——就像操作系统的安装指南和踩坑记录，不属于内核也不属于应用。

放在核心战略下、与内核/插件并列，是因为它和两个业务模块一样，是"必须持续维护的一等公民"。

## 包含什么

三个子模块，各管一件事：

| 子模块 | 文件 | 回答什么 | 更新方式 |
|---|---|---|---|
| [计划](./计划/计划.md) | `计划/计划.md` | 先做什么、后做什么、每步验收 | **随情况改** |
| └ 三步 | `计划/第1步-*.md` / `第2步-*.md` / `第3步-*.md` | 每步的详细任务与产出 | 随步骤推进改 |
| └ 进度锚点 | `计划/交接说明.md` | 归档后接上进度 | 归档前更新 |
| [经验](./经验/经验.md) | `经验/经验.md` | 踩过什么坑、怎么避免 | **只增不改** |
| └ 行为约束 | `经验/AI行为约束.md` | 六条铁律 + 12 条失败模式 | 只增 |
| └ 补救教训 | `经验/补救方案.md` | 决策网络反推文档的教训 | 归档为历史依据 |
| [方法](./方法/方法.md) | `方法/方法.md` | 怎么写、怎么验 | **可改** |
| └ 执行过程 | `方法/决策文件执行过程.md` | 情报分级 + 通读 + 三层验证 | 可改 |
| └ 完成标准 | `方法/决策文件标准.md` | 什么算写完 | 可改 |

## 维护规则

1. **计划随情况改**：DSH 更新、用户方向调整、发现更优顺序 → 直接改 `计划.md`，不留旧版本（git 保留现场）
2. **经验只增**：新踩的坑补进 `AI行为约束.md` 的失败模式档案；已有教训不删
3. **方法可改**：执行过程发现更有效的方式 → 改 `决策文件执行过程.md`，并说明改的理由
4. **不僵化**：任何"必须这样做"的规则，如果被证明阻碍执行，就改规则本身——规则服务于战略，不是反过来
5. **命名遵循决策网络**：文件 = 模块名；有子模块就建同名文件夹（`计划/计划.md`），不用 README.md
