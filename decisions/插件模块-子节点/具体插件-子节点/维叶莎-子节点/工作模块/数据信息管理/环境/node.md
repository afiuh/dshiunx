# 环境：笔记库与 pi 对话生态

**父模块**：`../node.md`

## 为什么存在

维叶莎的 skill 不能凭空写；必须先知道笔记库怎么运转、每个 pi 对话负责什么，否则 skill 会空泛/越权/乱改。

## 一、笔记库怎么运转

### 结构

- 一级文件夹 = 问题系统；每个文件夹有 `根声明.md`（为什么存在，不描述装什么）；
- `index.md` = 首页投影/入口：系统总览、根声明、引用网络；
- 文件树/标题层级/双链引用；改动前查引用影响，改名/移动查全库；
- `草稿集/` = 孵化区（人的草稿 + AI 产物）；
- `工具的使用/` = 工具手册 + 活跃项目台账；
- `记录类/` = 被动积累；`我的历史/` = 归档（只有追溯价值）。

### 维护

- 用户驱动：用户点题/发起时执行；AI 不自动维护；
- git 仓库 `~/obsidian-笔记`，远程 `obsidian-shuju`；改动分步 commit，前缀 `arch-obsidian:`；
- 变更后过《维护更新检查手册》（变更类型 → 检查清单）；
- 索引规则/禁忌/校验见《使用手册》：
  - 标题层级 = 文件夹层级；
  - 每个标题下带 `file:///` 位置链接；
  - 不物理移动系统目录；
  - 敏感文件（`~/.git-credentials`、`~/.dev-sidecar/*.key.pem`、`/etc/shadow`）不读不写；
  - 引用用户原话一字不改。

### 对 jarvis-notes 的约束

- 搜索用 `rg`；读取按相对路径；
- 写入默认草稿/inbox，指定路径要限制在笔记库内；
- 写入前备份、写入后记录（audit）；
- 改名/移动前查引用；不静默覆盖。

### 归档体系

- L0 `archives/INDEX.md`：会话地址；
- L1 各会话 `README.md`：阶段表；
- L2 阶段档案 `.md`：详细内容；
- L3 原始 `.jsonl`：完整对话；
- 调回：`pi --session <ID>`。

### 对 jarvis-dispatch 的约束

- 长任务从台账找负责对话，用 `pi --session <ID>` 拉起/继续；
- 不自己执行长任务；不替用户决定分配；
- 结果回传；项目完成后台账移除，内容交归档。

## 三、对其它 skill 的约束

- `jarvis-tasks`：事务系统 = 信息源（物品/人/活动主体）→ 推理 → 事务；先捕获到 inbox，不自动归档；正式表在 `具体安排工作区/记录.md`、`日常任务.md`。
- `jarvis-system`：本机 Arch/Hyprland；系统配置档案/根目录索引；不物理移动系统目录；敏感文件红线。
- `jarvis-memory`：可检索归档 L0-L3；不主动翻旧账；不记隐私。
- 工作 skill 隔离：放项目内 `skills/`，仅 jarvis 显式 `--skill` 加载。

## 验证

- skill 能引用真实路径/台账/维护规则；
- 不越权改笔记库/项目；
- 长任务能定位到正确对话；
- 写入可追溯。
