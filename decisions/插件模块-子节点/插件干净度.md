# 插件干净度

**父级**：[插件模块](../插件模块.md)

## 为什么需要

接下来要把各种"好东西"解耦化、插件化移进来。来源有四个：DSH 官方插件、用户 Arch 系统里的好设计、pi 本身的功能、用户亲自设计的机制。过程中还会冒出很多新需求。

**核心命题**（用户 2026-10-24）：

> "在这个过程中我们将会深入探索一件事：如何实现插件最大程度的功能干净，不需要什么版本限制，只要有功能都能成为我们项目的插件。"

不是"先移进来再说"，而是**每移一个，就用干净度判据检验**。不干净的插件会污染整个体系（状态串、依赖隐藏、卸载残留、版本门槛）。

## 用户原话

> "接下来的就要把各种好东西都解耦化插件化都移到我们的项目里，现在的好东西的参考来源一个是dsh的官方插件，一个是我的arch系统里面的好设计，还有pi本身的各种功能和我亲自设计的各种机制，在实际做的时候肯定还会有很多新的需求功能冒出来，先不列详细的插件计划，但是在这个过程中我们将会深入探索一件事，如何实现插件最大程度的功能干净，不需要什么版本限制，只要有功能都能成为我们项目的插件"

## 干净度判据（8 条，可验证）

| # | 判据 | 怎么验证 | 违反的后果 |
|---|---|---|---|
| 1 | **单一能力**：一个插件只做一件事 | 看包名/`name` 与职责是否一一对应 | 一个包塞多个能力 → 无法裁剪 |
| 2 | **显式依赖**：依赖只通过 `inject` 声明 | `grep` 该包的 import：有没有 import 其他具体插件 | 隐式依赖 → 卸载时连环崩 |
| 3 | **无全局状态**：状态在 session / storage，不在模块级变量 | 搜模块级 `let` / `Map` / 单例 | reload 后状态丢失/串台 |
| 4 | **可独立卸载**：所有副作用走 `ctx.effect` | 卸载后进程无残留（定时器/监听/子进程） | 内存/句柄泄漏 |
| 5 | **可替换**：服务契约不变，实现可换 | 换一个实现（native ↔ PTC ↔ 外部）不改调用方 | 实现锁死 |
| 6 | **无版本元数据**：没有 `version` / `engines` / `peerDependencies` 检查 | `grep` 该包 manifest 与加载路径 | 版本门槛（P7） |
| 7 | **可裁剪**：不装它，系统仍启动 | 从 profile 去掉 → `dx` 仍能跑 | 插件变成隐形依赖 |
| 8 | **不预设用法**：不内置"用户应该怎么用"的流程 | 看是否有硬编码的 UI/审批/菜单/默认开启 | 产品假设（主题 §2.0 禁止） |

**补充**：判据 6 不只是"不写版本号"，还包括**不读取别人的版本号做判断**——`engines` / `compatibleWith` / `updatable` / exemption 全部属于此类。

## 与现有决策的关系

| 决策 | 关系 |
|---|---|
| P2（一切皆插件） | 干净度是 P2 的操作化：不是"能挂上"，而是"挂得干净" |
| P7（无版本门槛） | 判据 6 直接落地；版本检查已从代码删除（缺口 12） |
| [插件规范](./插件基础设施-子节点/插件规范.md) | 判据 1-4 的契约细节（形态/生命周期/可重入） |
| [依赖边界](../内核模块-子节点/工程保障-子节点/依赖边界.md) | 判据 2 的机械检查（dependency-cruiser） |
| [插件装配](./插件基础设施-子节点/插件装配.md) | 判据 7 的裁剪方式（profile patch / bundles） |

## 不选什么

| 不选 | 为什么 |
|---|---|
| 先移进来，以后再解耦 | 解耦成本远高于一开始就按判据做（TUI 的教训：20 万行移进来后拆了几个月） |
| 用版本号做"能不能装"的判断 | 违反 P7；"能跑就是能跑" |
| 用插件市场/发布体系 | 产品包袱（DSH 的偏差） |
| 用"默认全开"的发行版 | 违反主题 §2.0（不预设用法） |

## 探索方式（不是计划）

1. **每移一个插件**：先过 8 条判据，不干净先改（解耦），再移
2. **遇到新需求**：先问"它该是插件还是内核能力"（P1 准入判据），再问"干净度 8 条"
3. **发现不干净**：记录到 [待办清单](../计划与经验-子节点/路线-子节点/待办清单.md)，作为缺口，不静默接受
4. **不列详细插件清单**：来源多、需求会变；判据稳定，清单不稳定

## 验证

- 每个移入的插件都能回答 8 条判据（有则 ✅，无则说明为什么豁免）
- 删掉任一插件，`dx` 仍能启动（判据 7）
- 插件 manifest 与加载路径中不出现版本判断（判据 6）
- 插件之间没有 import（判据 2）
