# 插件启停

**父级**：[插件演化](../插件演化.md)

## 为什么需要

插件要能开、能关、能删、能重装——否则"一切皆插件"就只是"一切皆默认开启"。

## 准备怎么实现

### 宏观想法

**启停只改装配层，不改插件代码**：

```
启用/禁用 → profiles/default/cordis.patch.yml 的 - id: xxx, disabled: true
删除     → bundles/*/cordis.patch.yml 移除条目 + npm run build:entries
卸载/重装 → plugin-manager 的 install/remove（安装流程）
```

**为什么禁用走 profile patch**：`entries.yml` 是生成物（[插件装配](../../插件装配.md)），手改会被 `build:entries` 覆盖；`cordis.patch.yml` 是用户层，按 id 覆盖，不会丢。

### 细节实现

1. **启用/禁用**：`profiles/default/cordis.patch.yml` 加 `- id: <插件 id>, disabled: true`；`disabled` 支持 `!!js` 条件（如 headless 模式禁用 TUI / credentials）。
2. **删除**：从 `bundles/<层>/cordis.patch.yml` 移除该条目（或整组），`npm run build:entries` 重新生成；`catalog.yml` 由 `npm run catalog` 同步。
3. **卸载/重装**：`plugin-manager` 的 `install` / `remove`（`dsh-plugin-manager`），走安装流程（快照 → 试装 → 校验 → 激活）。
4. **运行时启停**：`ctx.loader.create()` / `entry.update({ disabled })`；热加载下立即生效（见 [热加载与回滚](./热加载与回滚.md)）。
5. **边界**：不做版本管理（P7）——没有 `updatable` / `exemption` / 版本选择。
6. **裁剪 vs 漏挂**：有意删除要在决策里记录；漏挂是装配缺口（[插件装配](../../插件装配.md) 硬规则）。

### 边界

| 本节点负责 | 不负责 |
|---|---|
| 启用/禁用/删除/卸载的操作路径 | 插件怎么安装（[插件来源与安装](./插件来源与安装.md)） |
| profile patch 的 disabled 语义 | 插件怎么组合（[插件装配](../../插件装配.md)） |
| 运行时启停 | 版本管理（明确不做） |

### 验证

- `cordis.patch.yml` 加 `disabled: true` → 对应插件不挂载，其他插件正常
- 从 bundles 删除 + `build:entries` → entries.yml 不再含该条目
- `plugin-manager` 卸载后 profile 的 bundles 列表同步更新
- 运行时 `entry.update({ disabled: true })` 生效（HMR 下无需重启）

## 参考什么

- `profiles/default/cordis.patch.yml`（用户层 disabled）
- `bundles/*/cordis.patch.yml`（装配源）
- `packages/dsh-plugin-manager/src/index.ts`（install / remove）
- [插件装配](../../插件装配.md)（生成物 vs 源）
