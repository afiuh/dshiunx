# 观测

**父级**：[插件演化](../插件演化.md)

## 为什么需要

插件在运行时改自己（热更、AI 写、启停），出问题时必须能回答"哪个插件、哪一步、为什么"。没有观测，自进化就是黑箱。

## 准备怎么实现

### 宏观想法

四层观测，从轻到重：

```
日志（ctx.logger）→ 心跳（heartbeat）→ watchdog（空闲超时）→ 依赖图（deps / cruiser）
```

**为什么不做指标/追踪**：当前是单进程、单用户；日志 + 心跳足够定位。OpenTelemetry 那套留给多实例/远程部署，不进内核。

### 细节实现

1. **日志**：`ctx.logger`（`info` / `warn` / `error`），由 `cordis-plugin-logger-console` 导出到 stderr；启动期的日志在 `prepare` 回调里挂载导出器，避免 boot 期丢失。
2. **心跳**：`bin/dx.ts` 每 100ms 写 `DSHIUNX_HEARTBEAT`（默认 `/tmp/dshiunx-heartbeat`），退出时删除；外部 watchdog 可据此判断进程是否卡死。
3. **watchdog**：`dsh-timeout` 的 `idleWatchdog`（`packages/dsh-timeout/src/index.ts:124`）——LLM 流的空闲超时（`dsh-llm-deepseek` 的 `MESSAGES_IDLE`）。
4. **依赖图**：`scripts/deps.mjs`（tsconfig paths / entries 包检查）+ `.dependency-cruiser.cjs`（路径级依赖约束）。
5. **卡死诊断**：`installFailLoud`（`dsh-app-boot`）捕获 `unhandledRejection` / `uncaughtException`，先写诊断再释放终端；启动失败带 `StartupError`（配置路径 + 启动日志）。
6. **边界**：不采集遥测、不上报远程（P6 安全网：隔离 + 可观测 + 可回滚，观测是本地能力）。

### 边界

| 本节点负责 | 不负责 |
|---|---|
| 日志 / 心跳 / watchdog / 依赖图的用法 | 具体日志格式（各插件自己决定） |
| 卡死诊断的入口 | 性能剖析 / 分布式追踪 |
| 本地可观测性 | 远程遥测（明确不做） |

### 验证

- 启动失败时 stderr 有 `StartupError` + 启动日志
- `dx` 运行时 `/tmp/dshiunx-heartbeat` 持续更新，退出后删除
- `node scripts/deps.mjs check` 能报告 paths / entries 不一致

## 参考什么
