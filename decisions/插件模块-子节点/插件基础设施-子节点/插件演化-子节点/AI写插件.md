# AI写插件

**父级**：[插件演化](../插件演化.md)

## 为什么需要

P6（自进化）：AI 是内核的一部分，能在运行时改造系统。AI 写插件是这个能力的入口——但也是最大的风险源（AI 会犯错、会幻觉、会写出破坏契约的代码）。

## 准备怎么实现

### 宏观想法

**写 → 验 → 跑 → 回滚**，四步闭环；风险控制的细节在 [AI插件风险控制](../插件规范-子节点/AI插件风险控制.md)：

```
AI 生成（约束）→ 加载前验证 → 运行时监控 → 事后回滚
```

**为什么本节点不重复风险控制的内容**：本节点管"演化动作怎么走"（谁写、写什么、怎么进来），风险控制管"每个阶段的约束细节"（四阶段的具体规则）。

### 细节实现

1. **生成约束**：按 [插件规范](../插件规范.md)——ESM、静态 import、`ctx.effect` 清理、状态外置、入口声明（`name` / `apply` / `inject`）。
2. **加载前验证**：`AI插件风险控制.md` 的阶段 2——语法/类型/契约检查；不通过不进 loader。
3. **运行时监控**：日志 + watchdog（见 [观测](./观测.md)）；插件异常不拖垮整棵树（fiber 隔离）。
4. **回滚**：每步 git 提交（`decision(...)` / `feat(...)`）；出问题 `git revert`。不做运行时快照（checkpoint 是未来插件）。
5. **与内核的边界**：AI 写的插件**不能改内核**（P6：内核不可自进化）；只能通过 `ctx` 的公开能力（inject / provide / effect / tools / sessions）工作。
6. **与装配的关系**：AI 写的插件通过 loader 挂载（`ctx.loader.create()` / profile bundle），不绕过装配（见 [插件装配](../插件装配.md)）。

### 边界

| 本节点负责 | 不负责 |
|---|---|
| AI 写插件的流程（写→验→跑→回滚） | 每个阶段的具体约束（[AI插件风险控制](../插件规范-子节点/AI插件风险控制.md)） |
| AI 与内核的边界 | 插件市场 / 发布（P6 明确不做） |
| 回滚策略（git） | 运行时热快照（未来） |

### 验证

- AI 生成的插件能通过 `AI插件风险控制` 的四阶段
- 插件异常时进程不崩、其他插件继续运行
- 回滚后系统回到上一个可用状态（`git revert` + 重启）
