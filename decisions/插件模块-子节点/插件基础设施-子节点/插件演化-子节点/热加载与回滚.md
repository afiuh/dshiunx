# 热加载与回滚

**父级**：[插件演化](../插件演化.md)

## 为什么需要

改插件不重启进程（开发体验 + 自进化），改坏了能退回去（安全网）。

## 准备怎么实现

### 宏观想法

```
文件变化 → 依赖图 → 三集合（stashed/accepted/declined）→ partialReload → 状态迁移
                                                                      ↓
                                                              失败 → git 回滚 + 重启
```

**为什么热加载只换实现**：服务契约（name / inject / provide）不变，替换的只是插件内部实现——否则依赖它的插件会拿到不一致的接口。

### 细节实现

1. **触发条件**：`cordis-plugin-hmr` 监听 `root`（当前 `[packages]`），文件变化 + debounce（200ms）后重载对应插件入口。
2. **依赖图**：ESM `ModuleJob.linked`（运行时准确），不是静态分析（见 [热更新-子节点/依赖图](../../../../内核模块-子节点/热更新-子节点/依赖图.md)）。
3. **三集合**：stashed / accepted / declined——决定哪些插件重载、哪些保留（[三集合](../../../../内核模块-子节点/热更新-子节点/三集合.md)）。
4. **partialReload**：清模块缓存 + 重建 fiber（[partialReload](../../../../内核模块-子节点/热更新-子节点/partialReload.md)）。
5. **状态迁移**：`serialize` / `restore`（[状态迁移](../../../../内核模块-子节点/热更新-子节点/状态迁移.md)）；状态外置到 storage / session，不放模块级变量。
6. **reload 重入契约**：新 apply 先于旧清理执行（[Fiber.md](../../../../内核模块-子节点/依赖注入与生命周期-子节点/Fiber.md)「reload 时序」）——插件注册必须幂等（[插件规范](../../插件规范.md)「可重入」）。
7. **回滚**：git 每步提交，`git revert` + 重启；不做运行时快照（checkpoint 是未来插件）。
8. **边界**：HMR 挂载在 entries 顶层（[热更新.md](../../../../内核模块-子节点/热更新.md)「挂载位置」），不挂具体插件 group；`root` 的 watch 范围是显式 opt-in。

### 边界

| 本节点负责 | 不负责 |
|---|---|
| 热加载的触发/依赖图/重载/状态迁移 | HMR 的实现细节（内核模块-热更新） |
| 回滚策略（git） | 运行时快照 / checkpoint |
| 与插件契约的交互（重入幂等） | 服务契约本身（插件规范） |

### 验证

- 改插件入口 → 对应插件 reload，进程不退出
- 改深层依赖 → 依赖它的插件入口全部重载
- reload 后状态从 storage/session 恢复
- 改坏了 → `git revert` + 重启回到可用状态
