# dshiunx 决策网络

> **真源**：本目录（项目 git 管理）。obsidian 里只留指针。
> **结构**：文件夹嵌套 = 模块树，战略 → 战术 → 细节，无限细分，不设固定层数。
> **文件**：一个文件 = 一个模块；文件名 = 模块名（不用机器 ID）。
> **文件内部**：1/2/3 编号，讨论链自由叙述。
> **淘汰**：直接删除文件/文件夹；删除原因写进 commit message，git 历史保留现场。

## 命名与嵌套

| 角色 | 形式 | 例子 |
|---|---|---|
| **节点内容**（父文件） | `X.md`，与它的子文件夹**并列** | `插件基础设施/插件演化.md` |
| **子节点文件夹** | `X-子节点/`（`X` = 父文件名） | `插件基础设施/插件演化-子节点/` |
| **叶子节点** | `X.md`（无文件夹） | `插件基础设施/插件分类.md` |

**规则**：

1. **父文件与子文件永远不在同一个文件夹里**：`X.md` 与 `X-子节点/` 并列，父文件不在文件夹里
2. **同级文件永远在同一个文件夹里**：同一个父节点的所有子节点，都在 `X-子节点/` 里
3. **文件夹名里的 `X` 必须能唯一指向一个 `.md` 文件**；指不到说明决策网络缺节点，要补
4. **文件夹里只放子节点**，数量不限——1 个也可以（这一层真的只有一个子节点时，不要为了凑数打破层级）
5. **有规划未写**：建占位文件（父级 + 状态 + 范围），占位是为了让规划可见，不是为了凑数
6. **归档区例外**：`历史讨论-子节点/` 是只读归档，主题目录（TUI / 运行时能力 / 框架来源 / 架构分层 / Agent模式）不参与演化，不需要 `-子节点` 后缀和父文件

```
插件模块-子节点/                    ← 父文件：插件模块.md
├── 插件基础设施.md                 ← 节点内容
├── 插件基础设施-子节点/            ← 它的子节点
│   ├── 插件演化.md
│   ├── 插件演化-子节点/
│   │   ├── 插件来源与安装.md
│   │   └── 插件启停.md
│   ├── 插件分类.md                 ← 叶子
│   └── ...
└── 具体插件.md + 具体插件-子节点/
```

## 拆分规则

1. **每级只拆自己这一层**，不预告下一级
2. 文件名 = 模块名，不是决策标题
3. 文件内部 = 这个模块的决策（讨论链 + 决定）
4. 这个模块为什么存在、为什么放这里 → 由上一级文件记录
5. 淘汰的决策直接删除，commit message 写原因

## 提交约定

**Git 没有字数限制**（惯例：subject ≤ 72 字符，body 随意长）。能写详细就写详细。

```bash
# 决策变更（只改 decisions/）
git commit -m "decision(<路径>): <一句话>" -m "<详细说明>

背景：为什么讨论这件事
讨论链：起点 → 关键分歧 → 收敛
决定：选了什么
影响：哪些模块/决策受影响
相关：<其他决策路径或 commit>"

# 代码实现（引用决策路径）
git commit -m "feat(<模块>): <改动> (decisions/<路径>)" -m "<详细说明>"
```

## 代码改动必须同步决策

**改了哪个模块的代码，就在该模块的 README 里更新对应决策**——同一次提交，或紧跟着的提交。包括：

- 新增/修改的隐式行为 → 补进决策列表
- 与 DSH 的差异变化（比如消除了类型断言）→ 更新「与 DSH 差异」部分
- 决策与代码冲突 → 改代码或改决策，不留着

不需要用户提醒；决策网络必须和代码同步，否则它就只是文档。

## 删除约定

被淘汰的决策**直接删除**（文件/文件夹），不保留“已废弃”标记：

```bash
git commit -m "decision(<路径>): delete" -m "<详细说明>

删除原因：为什么淘汰
取代者：<新决策路径>（没有就写“无”）
影响面：哪些代码/模块需要跟着改
现场：git log -- decisions/<路径> 可查"
```

git 历史保留现场；`git log -- decisions/<路径>` 可查。
