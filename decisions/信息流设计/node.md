# 信息流设计

**父模块**：`../root.md`

## 为什么存在

语音、笔记、事务、pi 分配、系统控制、长期记忆不是孤立功能；它们之间需要明确“什么信息、从哪来、到哪去、谁消费、存哪”。没有信息流设计，功能会各自为政，助手无法串起来。

## 输入 / 输出

- 输入：手机录音按钮（trigger）、语音文本、当前上下文（项目/笔记/事务/会话）；
- 输出：意图/路由结果、执行结果、TTS/反馈、记录。

## 核心信息流

```
语音/按键
  → 文本
  → 意图/路由
      ├── 问答 → LLM/pi
      ├── 笔记 → 检索/读取/写入
      ├── 事务 → 结构化/写入
      ├── 任务 → 拉起 pi 对话
      └── 系统 → 应用/命令/窗口
  → 结果/反馈
  → TTS/UI/记录
```

## 边界

- 不替代各功能节点；只定义它们之间的接口/事件/上下文；
- 不预设固定流程；路由由具体情境决定；
- 技术细节（消息格式/队列/存储）后面打磨。

## 子节点（待展开）

- 输入事件：语音文本/按键/唤醒；
- 上下文/状态：当前项目/笔记/事务/会话；
- 意图/路由：怎么判断走哪条；
- 执行/工具：本地 skill / pi 对话 / 系统命令；
- 输出/反馈：TTS/UI/日志；
- 存储/持久化：SQLite/笔记库/事务系统/pi 会话。

## 验证

- 一句话能走通：输入 → 路由 → 执行 → 输出；
- 各功能节点通过接口连接，不各自读全局；
- 上下文/记录可追溯。
