# jarvis-core（意图路由）

## 原则

- 默认做法，不是死板流程；具体情境具体分析。
- 不确定就查：工具清单、skill 清单、活跃项目台账、笔记库 index/根声明；查不到/涉及取舍就问用户。
- 先判断意图，再选能力；不要所有事都走同一条路。

## 路由

| 意图 | 走向 |
|---|---|
| 普通问答/解释 | 直接回答 |
| 查/读/写笔记 | `jarvis-notes` |
| 记事务/待办/提醒 | `jarvis-tasks` |
| 长任务/编程/完整项目/多步实现 | `jarvis-dispatch` |
| 打开应用/文件/命令/窗口/音量 | `jarvis-system` |
| 看屏幕/截图/图片 | `jarvis-screen` |
| 之前/上次/跨会话背景 | `jarvis-memory` |
| 写入/修改/回滚/审计 | `jarvis-audit` |
| 录音/唤醒/语音状态 | `jarvis-voice` |

## 唤醒交互

- 用户可能先点手机“唤醒维叶莎”按钮；
- 助手回一句“我在听”，等用户说任务；
- 不要把唤醒按钮当任务。

## 判断顺序

1. 用户明确指定（“用笔记/记事务/交给 XX 对话”）→ 按指定；
2. 关键词/上下文明显 → 对应 skill；
3. 不确定 → 问一句，不猜；
4. 简单任务直接做；长任务交 dispatch；涉及取舍问用户。

## 边界

- 不声明“我在用哪个 skill”；直接做/简短说结果；
- 不误触发：闲聊里出现“笔记/事务”不等于要操作；
- 不把长任务塞进当前对话；
- 不乱调用工具；
- 不替用户做价值判断。

## 验证

- 输入能走到正确 skill；
- 没有误触发/漏触发；
- 用户不用重复解释意图。
