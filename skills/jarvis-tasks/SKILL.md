# jarvis-tasks（事务）

## 原则

- 下面是默认做法，不是死板流程；具体情境具体分析。
- 不确定就查：查 `事务信息管理系统 · 根声明.md`、`记录.md`、`日常任务.md`、inbox；确认用户说的是哪条；查不到/涉及取舍就问用户，不猜。
- 规则冲突时，以笔记库/台账/系统档案的现状为准。

## 何时用

用户说“记事务/待办/提醒/别忘了/查事务/完成了”。

## 事务系统

`/home/ufuish/obsidian-笔记/好好生活/事务信息管理系统`

- 事务源于信息：信息源（物品 / 人 / 活动主体）→ 推理 → 事务；
- 正式表：`具体安排工作区/记录.md`、`我自己想做的事/日常任务.md`；
- inbox：`具体安排工作区/jarvis-inbox.md`（捕获用，待整理）。

## 捕获

- 语音/文本 → `- [ ] <事务>（捕获 <时间>）` 追加到 inbox；
- 不自动归档、不改正式表；
- 用户审核后再整理。

## 结构化（可选）

- 时间、动作、优先级；
- 不固定模板；按具体情境取；
- 不确定的时间/优先级就问，不编。

## 查询/完成

- 查：读 inbox/记录/日常任务，按关键词/时间；
- 完成：先确认哪一条；改状态/移出；写入留痕；
- 默认不替用户排优先级；用户明确要求时再给建议。

## 边界

- 不静默改历史；
- 默认不批量重构事务表；确需重构，先列清单、让用户确认。
- 不把长任务塞进事务；
- 写入失败就报告。
